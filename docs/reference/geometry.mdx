A sketch draws in a geometry, and the flat plane is the default. `space` on the config names another one, and every word of the sketch reads it. `space` is the metric: what a small step is worth. `projection` is the chart: how the sheet shows the space. A chart changes no length, and the curvature survives every chart.

## space · projection

<include>/_sig/Toolkit.space.mdx</include>

`space: 'hyperbolic'` or `space.hyperbolic({ radius })` puts the sketch in the hyperbolic plane. `space: 'spherical'` or `space.spherical({ radius })` puts it on a sphere. The same numbers then name places in that space. Below, a walker takes five equal steps with a right turn between them. In the flat plane that walk never closes. In the hyperbolic plane it closes, and the cells of the `{5, 4}` tiling fill the disk around it.

```ts live
import { sketch, strokes, line, circle, space } from 'occlude';

export default sketch({ aspect: [1, 1], space: space.hyperbolic({ radius: 50 }) }, (t) => {
  const tiles = t.tiling(5, 4, { depth: 5 });
  const { cell } = tiles;
  // Five legs of the first cell, each a `step` of the cell's own side.
  const side = t.space.distance(cell[0], cell[1]);
  let st = t.station(cell[0]).toward(cell[1]);
  const legs = [];
  for (let i = 0; i < 5; i++) {
    const from = st;
    st = st.step(side);
    legs.push(line(from, st, { pen: 'stabilo-88-blue' }));
    if (i < 4) st = st.turn(90);
  }
  return [circle(t.space.center, 300), strokes(tiles, { pen: 'pigma-005-black' }), legs];
});
```

`projection` picks the chart. The hyperbolic plane has two charts. `'poincare'`, the default, keeps angles and draws a geodesic as an arc. `'klein'` draws every geodesic straight and does not keep angles. The sphere has three. `'stereographic'`, the default, keeps angles and shows the whole sphere. `'gnomonic'` draws every geodesic straight. `'orthographic'` is the view from far away. The last two show the near half only, and the far half draws nothing. A `projection` with no `space` is an error. The same program under `'klein'`:

```ts live
import { sketch, strokes, line, circle, space } from 'occlude';

export default sketch({ aspect: [1, 1], space: space.hyperbolic({ radius: 50 }), projection: 'klein' }, (t) => {
  const tiles = t.tiling(5, 4, { depth: 5 });
  const { cell } = tiles;
  // Five legs of the first cell, each a `step` of the cell's own side.
  const side = t.space.distance(cell[0], cell[1]);
  let st = t.station(cell[0]).toward(cell[1]);
  const legs = [];
  for (let i = 0; i < 5; i++) {
    const from = st;
    st = st.step(side);
    legs.push(line(from, st, { pen: 'stabilo-88-blue' }));
    if (i < 4) st = st.turn(90);
  }
  return [circle(t.space.center, 300), strokes(tiles, { pen: 'pigma-005-black' }), legs];
});
```

A coordinate is a position by steps from the centre. `(x, y)` is x along the base geodesic through the centre, then y at right angles to it. So a column of the sketch is a geodesic, and a row is a curve at one distance from the base. A shape is its anchor plus offsets, and an offset is a step. One step is one drawable unit at the centre. An edge draws as the image of the flat edge, so a row of a grid does not bend onto a geodesic. `line(a, b)` asks for the geodesic.

The four drawings below are one program: a grid of cells, a sampled ring and a scatter. Only the config differs. First the flat plane:


One number is the geometry: the curvature. `space: { curvature: K }` is the primary form. Below zero is hyperbolic, above zero is spherical, and zero is flat. `'hyperbolic'` reads its radius as `K = -4/radius²`, and `'spherical'` reads it as `K = +1/radius²`. A larger radius is flatter. Without `radius`, the disk bends over 1.25 times the half-diagonal of the drawable. The sphere bends over the half-diagonal divided by √2, which is half the side of a square drawable. Thus the middle row of a wide drawable stays less than a quarter turn from the centre, and the drawable stays on the near side of the sphere. `size` on the projection is how big the picture prints. It is the radius on the page of the rim of the disk, or of the equator. Without `size`, the disk prints as the biggest circle that the drawable holds, and all of the drawable is inside that circle. A wide drawable then prints small. `size` and `radius` are the two controls: a larger `size` prints the disk larger, and a larger `radius` makes the drawable fill more of the disk. Change `radius` and the geometry changes. Change `size` and the same drawing prints larger or smaller. Below, a curvature written as a number, and a disk printed at 44 units.

```ts live
import { sketch, rect, circle, strokes, pen, mm } from 'occlude';

export default sketch({
  aspect: [1, 1], seed: 6,
  space: { curvature: -4 / (34 * 34) },
  projection: { kind: 'poincare', size: 44 },
  pens: { ink: pen({ width: mm(0.3), color: '#23252B' }), edge: pen({ width: mm(0.6), color: '#8A857C' }) },
}, (t) => [
  ...t.grid({ cols: 7, rows: 7, gap: 3 })
    .map((c, k) => (k % 3 === 0 ? rect(c.x, c.y, c.w, c.h) : circle(c.cx, c.cy, Math.min(c.w, c.h) / 2))),
  strokes(t.sample(circle(50, 50, 30), { count: 64 }), { pen: 'edge' }),
]);
```

A bare length is a length in the space. So `t.scatter({ spacing: 5 })` spaces points by five units of the space. `mm()`, `w()`, `h()` and `s()` have two meanings. In an ink word (a pen, a fill or a modifier) they are lengths on the paper, because the pen is flat: `mm(0.4)` is 0.4 mm of ink wherever it lands. In geometry (a shape, `t.scatter`, `t.sample` and the words in the table) they change to drawable units, and the result is then a length in the space. The modifiers (`wobble`, `roughen`, `dash` and `deform`) change the ink, so each length that a modifier reads is a length on the paper. Every fill works on the paper, after the projection: a hatch, a stipple and a fill callback read lengths on the paper. These words read the metric today:

| verb | reads the metric | in a curved sketch |
|---|---|---|
| `t.sample` | yes | spaces the samples by arc length of the space |
| `m.resample` | with a space | the toolkit gives `t.sample` one, and a bare call measures flat |
| `m.along` | with a space | stations sit by arc length of the space, flat without one |
| `m.trim` | with a space | cuts each end by arc length of the space, flat without one |
| `t.scatter` | yes | `spacing` is a length of the space, and the density follows the coordinates |
| `t.throw` | yes | the points are uniform over the area of the space |
| `faces().measure()`, `face.area`, `face.perimeter` | with a space | area, perimeter, the inscribed circle and the field integral in the space; `centroid`, `orientation` and `elongation` stay in the coordinates |
| `t.voronoi` | no | flat cells in the coordinates |
| `t.tiling` | yes | the cell and the placements are the space's own |
| `t.distanceTo` | yes | distance by the metric, with every edge read as a geodesic |
| `t.travelTime` | yes | an arrival time is a length of the space over the speed |
| `m.steps` | with a space | a move is a step of the space, flat without one |
| `force.*` | with a space | distances and directions of the space, flat without one |
| `points.near`, `pairs`, `edges.near` | with a space | the radius is a length of the space, flat without one |
| `m.transform` | no | moves each vertex by an isometry of the space, and measures nothing |
| `t.hexes` | no | a flat lattice of cells, drawn through the placement |
| `t.isolines` | no | flat contours of the field |
| `t.noise` | no | flat coordinates in, one number out |
| `t.relax` | yes | the centroid of a cell is weighted by the area of the space |
| `t.settle` | yes | the demand is the area of the space, and `spacing` sets the capacity in it |
| `fill('hatch')` | no | flat rulings across the area |
| `m.map` | no | puts each vertex where the callback says |
| `m.warp` | no | a flat cage, corner for corner |

`t.material`, `t.sample`, `t.within` and `polygon` answer in sketch coordinates. The projection applies once, when the engine draws the ink. Pens, nib widths, dashes, the plan and the time estimate never read the space.

A `rect`, a `path` and a `polygon` go to the places that their numbers name. A round shape is steps from its centre, so a `circle` prints round under a conformal chart. The same is true for an `ellipse` and for the corners of an `ngon`, and the edges of an `ngon` are geodesics. `t.material` keeps the corners of a shape in every space: four for a `rect` and six for a hexagon. In a curved space it also writes the edge column `geodesic`. The value is 1 on the edges of a `line`, a `circle`, an `ellipse` and an `ngon`. It is 0 on the edges of a `rect`, a `path` and a `polygon`. `strokes`, `polygon` and `m.transform` keep an edge with the value 1 on the geodesic between its ends. So a material of a shape draws as the shape draws. `smooth` rounds the corners of the shape before the space places the shape. The loop of an area keeps the side that its winding names. This is also true when an edge is longer than half the circumference of the sphere.

On the sphere, the coordinates repeat. A coordinate beyond ±πR names a place again. The words that cut, join or measure in coordinates (`planarize`, `faces()` and `t.within`) then see two places where the sphere has one.

## t.space

<include>/_sig/Toolkit.space.mdx</include>

The geometry of the run, as read-only data. `kind` is `'euclidean'`, `'hyperbolic'` or `'spherical'`. `projection` is the chart, or `'none'` in the flat plane. `curvature` and `radius` are in drawable units. `center` is the point the coordinates start from.

The metric is on the record. `distance(a, b)` measures the geodesic between two points. `geodesic(a, b, u)` is the point a fraction `u` of the way along it. `exp(p, v)` steps `|v|` from `p` in the direction `v`, and `log(p, q)` reads that step back. `circle(c, r, count)` is the circle of the space: every point one step `r` from `c`. `density(p)` is the area of the space that one unit of coordinate area holds. `toChart(p)` and `fromChart(z)` convert to and from the model chart. `project(p)` is the place on the sheet, and a point with no place comes back non-finite. Every member takes and answers sketch coordinates.

Below, five circles of the space about the centre, eight units apart. The dots are nine equal fractions of one geodesic.

```ts live
import { sketch, stroke, dots, circle, space, pen, mm } from 'occlude';

export default sketch({ aspect: [1, 1], space: space.hyperbolic({ radius: 50 }), pens: { ink: pen({ width: mm(0.25), color: '#23252B' }), tap: pen({ width: mm(1.8), color: '#2457D6' }) } }, (t) => {
  const c = t.space.center;
  const far = t.space.exp(c, [60, -30]);
  return [
    circle(c, 300),
    t.times(5, (k) => { const ring = t.space.circle(c, 8 + k * 8, 96); return stroke([...ring, ring[0]]); }),
    dots(t.times(9, (k, u) => t.space.geodesic(c, far, u)), { pen: 'tap' }),
  ];
});
```

A placement is an isometry of the space. It moves a point, a station, a material or a whole drawing, and it keeps every length and every angle. `orientation` is `1` when it keeps the hand of a motif and `-1` when it turns the motif over.

Four ways to get one: `station.placement()` carries the origin station, at `(0, 0)` facing `+x`, to that station. `between(door, from, to)` carries one station onto another, and `{ mirror: true }` turns it over on the way. A tiling gives one for each copy of its cell. `reflection(door, a, b)` is the mirror in the geodesic through two points, and `t.space.model` is the door of the sketch's space. Three ways to use one: `group(placement, …children)` draws a subtree there. `m.transform(placement)` moves a material and keeps every id. `placement.station(s)` moves a station and its heading. `a.then(b)` applies `a` and then `b`, and `a.inverse()` undoes `a`.

A placing group and a deforming group never share a group. Nest them: the inner group holds `translate`, `rotate` or `scale` in the motif's own coordinates, and the outer group holds the placement. The library refuses a group that names both, and the error names the keys.

Below, one arrow motif, written once about the origin. `group(s.placement(), arrow)` puts it at each corner of the cell (black). The blue copies go through `m.transform` and then the mirror in the first side. A mirror turns a motif over, so the barbs lean the other way. The green arrow is the first corner's arrow, carried to the third corner by `between(door, from, to, { mirror: true })`. It stands at that corner turned over, so it points the other way along the side.

```ts live
import { sketch, group, strokes, line, circle, space, reflection, between } from 'occlude';

export default sketch({ aspect: [1, 1], space: space.hyperbolic({ radius: 50 }) }, (t) => {
  const tiles = t.tiling(5, 4, { depth: 1 });
  const { cell } = tiles;
  const stops = cell.map((v, i) => t.station(v).toward(cell[(i + 1) % cell.length]));
  const arrow = [line(0, 0, 6, 0), line(6, 0, 3.4, 1.7), line(6, 0, 3.4, -1.7)];
  const motif = t.material(...arrow);
  const mirror = reflection(t.space.model, cell[0], cell[1]);
  return [
    circle(t.space.center, 300),
    strokes(tiles, { pen: 'pigma-005-black' }),
    stops.map((s) => group(s.placement(), arrow)),
    stops.map((s) => strokes(motif.transform(s.placement().then(mirror)), { pen: 'stabilo-88-blue' })),
    strokes(motif.transform(stops[0].placement().then(between(t.space.model, stops[0], stops[2], { mirror: true }))), { pen: 'stabilo-88-green' }),
  ];
});
```

The regular tiling of `p`-gons, `q` at every corner. The symbol picks the geometry: `(p − 2)(q − 2)` below 4 is the sphere, 4 the plane, and above 4 the hyperbolic disk. `{3, 5}` is the icosahedron, `{4, 4}` the square grid, and `{7, 3}` the heptagonal tiling of the disk. The sketch's `space` must be the geometry of the symbol, and the error names the `space` a symbol needs.

The answer is a [material](/docs/reference/material). Two cells that meet share their wall, so `strokes(tiles)` draws it once, and `tiles.faces()` gives the cells. `cell` is the first cell's corners, in order. `placements` is one [placement](#placement) for each copy, the identity first, so a motif drawn once in the cell goes to every copy. `tiles.seed` is the first face. Every face carries `generation` (reflections from the first cell), `mirrored` (1 for a copy that turns the plane over) and `placementIndex`.

`depth` is generations of reflection across the cell's edges. A spherical tiling is finite and comes back whole. `side` sets the wall length of a flat tiling, and a curved symbol refuses it, because its curvature fixes the side. Below, a `{7, 3}`, with the mirrored cells hatched blue.

```ts live
import { sketch, strokes, polygon, fill, circle, pen, mm, space } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 1, space: space.hyperbolic({ radius: 47 }), pens: {
  wall: pen({ width: mm(0.25), color: '#23252B' }),
  turned: pen({ width: mm(0.2), color: '#2457D6' }),
} }, (t) => {
  // A tiling is a material: shared corners, shared walls, and cells with a
  // generation and a hand to them.
  const tiles = t.tiling(7, 3, { depth: 4 });
  const c = t.space.center;
  const hatch = fill('hatch', { angle: 30, spacing: mm(0.9) });
  return [
    // The fills go down first. A fill is opaque, and it would hide a wall
    // drawn under it.
    tiles.faces().filter((f) => f.mirrored).map((f) => polygon(f, { fill: hatch, fillPen: 'turned', stroke: false })),
    circle(c[0], c[1], 300, { pen: 'wall' }),
    // Every wall once, whichever two cells share it.
    strokes(tiles, { pen: 'wall' }),
  ];
});
```

## t.distanceTo() in a space

<include>/_sig/Toolkit.distanceTo.mdx</include>

`t.distanceTo` measures by the metric of the sketch. In a flat sketch it is the straight-line distance, and in a curved one it is the distance of the space. Its field goes to `t.isolines`, `t.scatter`, `t.within` and the `sdf` algebra as any field does. It reads every edge as a geodesic. An open shape has no inside, so `t.distanceTo(line(a, b))` is the signed distance to one geodesic, positive on its left. Points have no inside too, so `t.distanceTo(points)` is zero at each point and minus the distance of the space to the nearest point everywhere else. The pure `sdf.*` words and `distanceToPoints` stay flat, because a pure kernel reads no frame.

Below, the cell of a `{7, 3}` inset at three fractions of its depth. One `t.isolines` call makes the insets once, and `m.transform` carries them to every copy.

```ts live
import { sketch, strokes, circle, pen, mm, space } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 1, space: space.hyperbolic({ radius: 47 }), pens: {
  edge: pen({ width: mm(0.3), color: '#23252B' }),
  inset: pen({ width: mm(0.2), color: '#2457D6' }),
} }, (t) => {
  const tiles = t.tiling(7, 3, { depth: 3 });
  const field = t.distanceTo(tiles.cell);
  // The deepest point of the cell is its centre, and the field reads it there.
  const deep = field(...t.space.center);
  const insets = t.isolines(field, [0.25, 0.5, 0.75].map((u) => deep * u), { step: mm(0.4) });
  return [
    circle(t.space.center, 300, { pen: 'edge' }),
    strokes(tiles, { pen: 'edge' }),
    tiles.placements.map((f) => strokes(insets.transform(f), { pen: 'inset' })),
  ];
});
```

The curves at one distance from a geodesic are not geodesics. Below, a piece of one geodesic in black, and the curves at fixed distances from it in blue. They run beside it and meet the rim where the geodesic does.

```ts live
import { sketch, strokes, circle, line, pen, mm, space } from 'occlude';

export default sketch({ aspect: [1, 1], space: space.hyperbolic({ radius: 47 }), pens: {
  rim: pen({ width: mm(0.3), color: '#23252B' }),
  near: pen({ width: mm(0.25), color: '#2457D6' }),
} }, (t) => {
  const [cx, cy] = t.space.center;
  const a = [cx - 42, cy - 18], b = [cx + 42, cy + 18];
  const across = t.distanceTo(line(a, b));
  return [
    circle(t.space.center, 300, { pen: 'rim' }),
    line(a, b, { pen: 'rim' }),
    strokes(t.isolines(across, [-30, -20, -10, 10, 20, 30], { step: mm(0.4) }).edges.filter((e) => !e.attrs.cut), { pen: 'near' }),
  ];
});
```

## fields and forces in a space

A field is a function of sketch coordinates. The engine samples a field on the paper. It reads each sample at the sketch point under that place of the sheet. So a `decimate` field, a fill field and a `t.within(field, area)` bound land where the ink of the same numbers lands. A sample at a place that the chart does not show reads 0. A `within` bound goes through the same lowering as the ink. Where the bound goes off the sheet, the engine joins the two ends of the visible part with a straight line.

A material from the toolkit knows the space of its coordinates, as `m.space`. `m.steps` moves each point by a step of that space. The forces measure distance and direction in it. `material(points)` knows no space, and it moves and measures flat. `t.travelTime` measures the walk in the space, and `t.relax` and `t.settle` weigh each cell by the area of the space.

Some words stay words of the chart. `t.voronoi` makes the cells of the coordinates. The `step` of `t.isolines` is a coordinate step. `t.hexes` and `t.grid` are flat lattices, and `t.streamlines` follows the field in coordinates. A hatch `spacing` is a length on the paper, and `t.noise` reads flat coordinates.

Below, the field of one cell of a `{5, 4}` tiling sets the hatch spacing of each cell. The field is zero on the walls of that cell. It falls with the distance of the space, so the hatch is tight on the cell and opens toward the rim. The dots are a scatter inside a circle of the space. `t.force.separation` then pushes them apart by steps of the space. They keep one spacing of the space from the centre to the rim.

```ts live
import { sketch, polygon, strokes, dots, fill, circle, mul, pen, mm, space } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 4, space: space.hyperbolic({ radius: 50 }), pens: {
  wall: pen({ width: mm(0.25), color: '#23252B' }),
  hatch: pen({ width: mm(0.2), color: '#2457D6' }),
  dot: pen({ width: mm(0.9), color: '#D2462E' }),
} }, (t) => {
  const tiles = t.tiling(5, 4, { depth: 4 });
  // The field of one cell, in the space: 0 on its walls, negative outside.
  const near = t.distanceTo(tiles.cell);
  // Each cell's hatch spacing grows with the cell's distance from that one,
  // measured in the space at the cell's centroid.
  const hatchAt = (f) => fill('hatch', { angle: 30, spacing: mm(0.5 + Math.max(0, -near(...f.centroid)) / 10) });
  // A move is a step of the space, and the force measures in the space.
  const pts = t.scatter({ spacing: 7, within: circle(t.space.center, 62) }).steps(12, (cur, next) => {
    const apart = t.force.separation(cur, { radius: 7 });
    next.move(cur.points, (p) => mul(apart(p), 0.15));
  });
  return [
    tiles.faces().map((f) => polygon(f, { fill: hatchAt(f), fillPen: 'hatch', stroke: false })),
    strokes(tiles, { pen: 'wall' }),
    circle(t.space.center, 300, { pen: 'wall' }),
    dots(pts, { pen: 'dot' }),
  ];
});
```

`view` does not take a space yet. Until it does, three words in `occlude/3d` hold a hyperbolic scene. They work in the Klein ball, the unit ball of `[x, y, z]`. There a hyperbolic line is a chord, and a hyperbolic plane is a flat plane. Klein coordinates are not hyperbolic lengths: a point at distance `R` from the centre sits at Klein radius `tanh R`.

`honeycomb(p, q, r, { depth })` gives the honeycomb as one complex. `cell` is the regular cell as a mesh. `placements` has one `Placement3` for each copy of the cell, and the identity is first. `points` has each corner one time, and two cells that touch at a corner share it. `faces` has each wall one time, with the columns `cell`, `generation` and `mirrored`. `cell` is the first copy that has the wall. `generation` is the number of reflections to that copy. `mirrored` is true when that copy is a mirror image. `wires` has each edge one time, as a wire with two points, and each wire has the columns `cell` and `generation`. The complex is not a mesh, because more than two walls touch each edge.

Four symbols have a compact cell: `{4, 3, 5}`, `{5, 3, 4}`, `{3, 5, 3}` and `{5, 3, 5}`. The word refuses any other symbol, and the error names its geometry.

`observer(eye, target, { up })` is the `Placement3` that moves `eye` to the centre of the ball and turns `target` onto `+Y`. The Klein model keeps angles at its centre, so the picture from there has the angles of the space itself. `transform(placement)` on a mesh or on wires moves each point with `placement.point`, and keeps each id and each column. A chord stays a chord, so two points draw a hyperbolic line exactly. `geodesic3(a, b, { count })` puts points along the chord at equal hyperbolic distances. Use it to measure along a line, not to draw one.

Below, the `{5, 3, 4}` honeycomb, four right-angled dodecahedra around every edge, seen from inside one cell. The honeycomb is its wires, because solid walls would hide every other cell. The heavier pen draws the room the observer stands in. That room is generation 0. The page edge cuts the wires.

```ts live
import { sketchAsync, strokes, clip, rect, pen, mm } from 'occlude';
import { view, perspective, honeycomb, observer } from 'occlude/3d';

export default sketchAsync({ aspect: [1, 1], pens: {
  ink: pen({ width: mm(0.18), color: '#46505C' }),
  room: pen({ width: mm(0.38), color: '#18202A' }),
} }, async (t) => {
  const b = t.bounds();
  const h = honeycomb(5, 3, 4, { depth: 2 });
  const c = h.cell.points.at(0);
  const toward = (f) => f.center[0] * c.x + f.center[1] * c.y + f.center[2] * c.z;
  const wall = [...h.cell.faces].reduce((f, g) => (toward(f) < toward(g) ? f : g));
  const seen = observer([c.x * 0.15, c.y * 0.15, c.z * 0.15], wall.center, { up: [0.26, 0, 0.97] });
  const camera = perspective({ eye: [0, 0, 0], target: [0, 1, 0], fovDegrees: 100, near: 0.005 });
  return view(h.wires.transform(seen), { camera, stroke: 'ink' }, (lines) => clip(rect(0, 0, b.w, b.h), [
    strokes(lines.visible.filter((w) => w.attributes.generation > 0), { stroke: 'ink' }),
    strokes(lines.visible.filter((w) => w.attributes.generation === 0), { stroke: 'room' }),
  ]));
});
```

## points along a geodesic

`geodesic3(a, b, { count })` puts `count` steps of equal hyperbolic length along the chord from `a` to `b`. Near the rim of the ball the same length is a shorter chord, so the beads crowd toward the edge. The picture looks straight down the `z` axis, so each chord draws as itself.

```ts live
import { sketchAsync, strokes } from 'occlude';
import { view, orthographic, polyline, circle, geodesic3 } from 'occlude/3d';

export default sketchAsync({ aspect: [1, 1] }, async () => {
  // Two chords of the ball: one through the centre, one off it. Each bead
  // is a short tick across the chord, one per step of equal hyperbolic
  // length.
  const chords = [[[-0.92, 0, 0], [0.92, 0, 0]], [[-0.55, 0.62, 0], [0.74, 0.38, 0]]];
  const wires = [circle(1)];
  for (const [a, b] of chords) {
    wires.push(polyline([a, b]));
    const dx = b[0] - a[0];
    const dy = b[1] - a[1];
    const len = Math.hypot(dx, dy);
    const nx = (-dy / len) * 0.035;
    const ny = (dx / len) * 0.035;
    for (const p of geodesic3(a, b, { count: 14 })) {
      wires.push(polyline([[p[0] - nx, p[1] - ny, 0], [p[0] + nx, p[1] + ny, 0]]));
    }
  }
  return view(wires, { camera: orthographic({ eye: [0, 0, 4], target: [0, 0, 0], up: [0, 1, 0], span: 2.3 }), stroke: 'ink' }, (lines) => strokes(lines.visible));
});
```

## a tiling of the sphere

The same `t.tiling` in a spherical sketch. `{3, 5}` is the icosahedron, and it comes back whole: 12 corners, 30 walls and 20 faces. The walls on the back of the sphere are the outer arcs of the picture. Of the three generations nearest the front, a hatch marks every other one, and a dot marks the middle of each cell.

```ts live
import { sketch, strokes, polygon, dots, fill, pen, mm, space } from 'occlude';

export default sketch({
  aspect: [1, 1], seed: 4,
  space: space.spherical({ radius: 30 }), projection: { kind: 'stereographic', size: 38 },
  pens: {
    wall: pen({ width: mm(0.3), color: '#23252B' }),
    tone: pen({ width: mm(0.18), color: '#B4552B' }),
  },
}, (t) => {
  const tiles = t.tiling(3, 5);
  // The generation of a cell is how many folds it took to reach it, and on
  // a sphere that is how far round it sits. Three of them is the front.
  const near = tiles.faces().filter((f) => f.generation < 3);
  return [
    near.filter((f) => f.generation % 2 === 0)
      .map((f) => polygon(f, { fill: fill('hatch', { angle: 20, spacing: mm(1.2) }), fillPen: 'tone', stroke: false })),
    dots(near.map((f) => f.centroid), { pen: 'wall' }),
    strokes(tiles, { pen: 'wall' }),
  ];
});
```
