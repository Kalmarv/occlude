A sketch draws in a geometry. The flat plane is the default. `space` on the config names another one, and every word of the sketch then reads it. There is one way to draw in a curved geometry, and this page holds it.

A coordinate system is a chart. It renames points and changes no length. Hyperbolic geometry is a metric. It says what a small step is worth, and its curvature survives every chart. The frame holds both: a `space` for the metric and a `projection` for the chart the sheet is drawn in.

## space · projection

<include>/_sig/Toolkit.space.mdx</include>

`space` sets the geometry the sketch draws in. Leave it out and the sketch draws in the flat plane, exactly as it always did. Set `space: 'hyperbolic'` and the drawable sits inside a Poincaré disk. The centre of the disk is the centre of the drawable. Its rim is the horizon, and the horizon lies infinitely far away. A step near the rim is worth more than a step at the centre. The same shape takes less room there.

`projection` sets the chart that carries the space to the sheet. The default is `'poincare'`. It keeps angles and bends a straight line into an arc. `'klein'` draws a straight line straight and does not keep angles. A `projection` with no `space` is an error, and the message names the space it needs.

`radius` is the knob: `space.hyperbolic({ radius: 50 })` puts the horizon 50 drawable units from the centre. A larger radius is flatter, and the flat plane is the limit as the radius grows. Without `radius` the horizon is 1.25 times the half-diagonal of the drawable, so the corners of the drawable lie inside it.

Set `space: 'spherical'` and the drawable becomes the picture of a sphere. The sphere touches the sheet at the centre of the drawable. A step near the centre is worth more than a step away from it. The same shape takes more room out there. The sphere is the opposite of the disk, and the knob is the same one. `space.spherical({ radius: 30 })` gives the sphere a radius of 30 drawable units. A larger radius is flatter. Without `radius` the sphere takes half the short side of the drawable. The equator of the sphere is the circle at twice the radius from the centre. The near half of the sphere lies inside that circle.

Spherical space has three charts. `'stereographic'` is the default. It keeps angles, and it shows the whole sphere: the one point opposite the centre is the outside of the picture. `'gnomonic'` draws every geodesic straight. `'orthographic'` shows the sphere from far away, inside a circle of one radius. The last two show one half of the sphere only. A point on the far half has no place on the sheet, so it draws nothing. Two dimensions have no occlusion. The engine drops the far half. It does not hide it behind the near half. A stroke that crosses the equator stops there, and it gets no new edge along the equator. Under `'gnomonic'` the equator lies infinitely far away, so keep such a drawing well inside the near half.

A bare number is a length **in the space**. A physical length is a length **on the paper**. `t.scatter({ spacing: 5 })` asks for five drawable units of the space between points, so the points crowd toward the horizon. `mm(0.4)` is 0.4 mm of ink wherever it lands, because the pen is flat. `w()`, `h()` and `s()` are percentages of the drawable, so they are paper lengths too.

These words read the space in this build. A `circle` shape is the circle of the space. Every edge of a lowered shape is a geodesic. `t.material`, `t.sample`, `t.within` and `polygon` answer in the chart. The chart is where a sketch computes. The projection applies once, at the moment the engine draws the ink. `t.sample`, `m.resample`, `m.along` and `m.trim` measure arc length by the metric of the space. The toolkit hands them that space. A bare `m.resample` call measures flat. `t.scatter` reads `spacing` as a length in the space, and it draws out to where the chart shrinks a step six-fold. `t.tiling` and `t.distanceTo` read it too, and they have sections of their own below.

Every other word draws through the projection and measures in the chart. `t.grid`, `t.hexes`, `t.isolines`, `t.noise`, `t.relax`, `t.settle` and `fill('hatch')` are the ones to know about. Pens, nib widths, dashes, the plan and the time estimate are never in the space, because paper is flat.

The four drawings below are one program. Only the config differs. The first is flat.

  t.grid({ cols: 5, rows: 5, gap: 4 })

## t.space

<include>/_sig/Toolkit.space.mdx</include>

`t.space` is the geometry of the run, as data. It is read-only, because the space is a frame setting and it is fixed for the run.

`kind` is `'euclidean'`, `'hyperbolic'` or `'spherical'`. `projection` is the chart, or `'none'` in the flat plane. `curvature` and `radius` are in drawable units. `center` is the chart point the space is centred on.

The metric itself is on the record. `distance(a, b)` measures the geodesic between two points. `geodesic(a, b, t)` gives the point a fraction of the way along it. `exp(p, v)` moves from a point, and `log(p, q)` reads the direction and the distance back. `circle(c, r, count)` is the circle of the space as chart points. `density(p)` is the area of the space one unit of chart area holds. It is 1 at the centre. It is NaN where the chart holds no place, which is the horizon of the disk and everything past it. `project(p)` is the chart-to-sheet map the ink door applies.

Every one of these takes and answers chart points, in drawable units. The flat plane fills them with the formulas the spacing words always used.

## t.tiling()

<include>/_sig/Toolkit.tiling.mdx</include>

The regular tiling with `p`-gons meeting `q` at a vertex. The symbol picks the geometry, and there is nothing to set. `(p − 2)(q − 2)` below 4 is the sphere, exactly 4 the plane, and above 4 the hyperbolic disk. So `{3, 5}` gives the icosahedron. `{4, 4}` gives the square grid. `{7, 3}` gives the heptagonal tiling of the disk. One word draws all three, and only `p` or `q` below 3 is a mistake.

The answer is data. `cell` is the fundamental polygon, `p` vertices in order, in drawable coordinates. `placements` is one point map for each copy of that cell, the identity first. Draw the motif once inside the cell and hand every placement to [m.map()](/docs/reference/transforms#mmap), or map the points yourself. The shape of the answer does not change with the geometry, so neither does the sketch around it.

`depth` is generations of reflection across the edges of the cell. Depth 1 is the cell and its `p` edge neighbours. A spherical tiling is finite. It has 4, 6, 8, 12 or 20 cells and no more. It comes back whole, and `depth` does nothing.

The word is on the toolkit, because a tiling needs the frame. Each geometry writes its tiling in its own model chart, and the chart has to land somewhere before a sketch can draw it. Where it lands follows one rule. When the `space` of the sketch is the geometry of the symbol, the model chart is the sketch's own. The placements are then isometries of the space the sketch draws in, and the cell is one cell of it. When the two do not agree, the model chart is fitted to the drawable: its unit circle becomes the largest circle the drawable holds. The answer is the Circle Limit picture, drawn as a picture on a flat sheet. The flat plane fixes no unit of length, so a Euclidean symbol always takes that fit. A scaled tiling of the plane is still a tiling of the plane.

Below, a `{7, 3}` in a hyperbolic sketch. The cell and the motif inside it are the same size everywhere, in the metric of the space. Every placement is a fold, and a fold turns the plane over, so the copies at odd generations take the second pen. The rim is one more circle of the space, drawn at a radius far out toward the horizon.

```ts live
import { sketch, strokes, circle, connect, pen, mm, space } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 1, space: space.hyperbolic({ radius: 47 }), pens: {
  even: pen({ width: mm(0.25), color: '#23252B' }),
  odd: pen({ width: mm(0.25), color: '#2457D6' }),
} }, (t) => {
  const { cell, placements } = t.tiling(7, 3, { depth: 4 });
  const c = t.space.center;
  // The motif, built once inside the cell: the middle of each edge,
  // joined up. Every segment of it draws as a geodesic.
  const motif = connect.ring(t.times(7, (i) => t.space.geodesic(cell[i], cell[(i + 1) % 7], 0.5)));
  // A copy at an odd generation is left-handed. The signed area of the
  // placed cell says which hand a copy has.
  const hand = (f) => {
    const q = cell.map(f);
    return q.reduce((s, a, i) => s + a[0] * q[(i + 1) % q.length][1] - q[(i + 1) % q.length][0] * a[1], 0);
  };
  return [
    circle(c[0], c[1], 300, { pen: 'even' }),
    placements.map((f) => {
      const ink = hand(f) < 0 ? 'odd' : 'even';
      return [strokes(motif.map(f), { pen: ink }), circle(f(c)[0], f(c)[1], 1.6, { pen: ink })];
    }),
  ];
});
```

One motif in three geometries, in a flat sketch. Each tiling is fitted to the drawable, so each one lands in the middle. The sketch moves the copies apart and scales the Euclidean one down, because a placement is a plain point map and a sketch can compose it.

```ts live
import { sketch, stroke, clip, circle } from 'occlude';

export default sketch({ aspect: [3, 1] }, (t) => {
  // `reach` keeps the copies whose centre is near enough the middle of
  // the chart to draw: on the sphere that is the near half of it.
  const panel = (p, q, depth, dx, k, reach) => {
    const { cell, placements } = t.tiling(p, q, { depth });
    const put = (v) => [150 + dx + (v[0] - 150) * k, 50 + (v[1] - 50) * k];
    const inner = cell.map((v, i) => {
      const w = cell[(i + 1) % cell.length];
      return [150 + ((v[0] + w[0]) / 2 - 150) * 0.78, 50 + ((v[1] + w[1]) / 2 - 50) * 0.78];
    });
    const near = placements.filter((f) => Math.hypot(f([150, 50])[0] - 150, f([150, 50])[1] - 50) <= reach);
    return clip(circle(150 + dx, 50, 46), near.flatMap((f) => [cell, inner].map((loop) =>
      stroke([...loop, loop[0]].map((v) => put(f(v)))))));
  };
  return [panel(3, 5, 0, -100, 0.78, 50), panel(4, 4, 3, 0, 0.3, 450), panel(7, 3, 3, 100, 0.9, 50)];
});
```

## t.distanceTo() in a space

<include>/_sig/Toolkit.distanceTo.mdx</include>

`t.distanceTo` reads the space. In a flat sketch it is the straight-line distance it has always been. In a curved one it measures by the metric, and the field it hands back is the one `t.isolines`, `t.scatter`, `t.within` and the `sdf` algebra already eat.

A `circle` shape is the circle of the space, so the field is the signed distance to it: the radius at the centre, zero on the loop, negative outside. Every other area is read as a polygon of geodesics. The value at a point is its distance to the nearest edge, positive inside. That is exact for a convex cell, and a tiling cell is one. An open shape has no inside, so `t.distanceTo(line(a, b))` is the signed distance to one geodesic. It is positive on the left of `a → b`, and `t.isolines` over it draws the equidistant curves of that geodesic.

The pure `sdf.*` words stay flat. A pure kernel never reads a frame. `t.distanceTo` is the door that does.

Past the horizon of the disk there is no place, and the field answers NaN there. Every field consumer already reads a non-finite sample as absent: `t.isolines` truncates a contour open at it, and `t.scatter` places nothing. The rim becomes the edge of the drawing with no special case.

Below, the cell of a `{7, 3}` contoured at a few steps of its own distance field. Each contour is the set of points one fixed distance in from the boundary. The contours crowd the way the metric crowds, not the way the sheet does. One `t.isolines` call gives the insets once, and every placement carries them.

```ts live
import { sketch, strokes, circle, connect, pen, mm, space } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 1, space: space.hyperbolic({ radius: 47 }), pens: {
  edge: pen({ width: mm(0.3), color: '#23252B' }),
  inset: pen({ width: mm(0.2), color: '#2457D6' }),
} }, (t) => {
  const { cell, placements } = t.tiling(7, 3, { depth: 3 });
  const c = t.space.center;
  const field = t.distanceTo(cell);
  // The deepest the cell goes is its inradius, which the field reads off
  // at the centre. The insets are three fractions of that.
  const deep = field(c[0], c[1]);
  const insets = t.isolines(field, [0.25, 0.5, 0.75].map((u) => deep * u), { step: mm(0.4) });
  const edges = connect.ring(cell);
  return [
    circle(c[0], c[1], 300, { pen: 'edge' }),
    placements.map((f) => [
      strokes(edges.map(f), { pen: 'edge' }),
      strokes(insets.map(f), { pen: 'inset' }),
    ]),
  ];
});
```

Two discs of the space, filleted where they meet, and one geodesic with its equidistant curves. `sdf.blend` never learns that its two leaves measure in another metric. The blue rings are the levels inside the pair, and the orange rings the levels outside. Far from the joint the blend is the union, so the outer rings keep the two corners. The grey curves are the family `t.isolines` draws over the field of the line. They run alongside the geodesic and close in on its two ends.

```ts live
import { sketch, strokes, circle, line, sdf, pen, mm, space } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 3, space: space.hyperbolic({ radius: 47 }), pens: {
  rim: pen({ width: mm(0.4), color: '#23252B' }),
  arc: pen({ width: mm(0.18), color: '#9AA3B2' }),
  inside: pen({ width: mm(0.25), color: '#2457D6' }),
  outside: pen({ width: mm(0.2), color: '#B4552B' }),
} }, (t) => {
  const c = t.space.center;
  const left = t.space.exp(c, [-14, -4]);
  const right = t.space.exp(c, [15, 6]);
  const pair = sdf.blend(t.distanceTo(circle(left[0], left[1], 22)), t.distanceTo(circle(right[0], right[1], 22)), 8);
  // One geodesic, near enough the whole way across the disk, and the
  // curves at a fixed distance from it.
  const across = t.distanceTo(line(c[0] - 42, c[1] - 18, c[0] + 42, c[1] + 18));
  return [
    circle(c[0], c[1], 300, { pen: 'rim' }),
    strokes(t.isolines(across, { spacing: 24 }, { step: mm(0.4) }), { pen: 'arc' }),
    strokes(t.isolines(pair, [18, 12, 6, 0], { step: mm(0.4) }), { pen: 'inside' }),
    strokes(t.isolines(pair, [-8, -18, -30, -44], { step: mm(0.4) }), { pen: 'outside' }),
  ];
});
```

## hyperbolic space in 3D

<include>/_sig/3d.honeycomb.mdx</include>

`view` does not take a space yet. Until it does, the three words a hyperbolic scene needs live in `occlude/3d`, spelled bare like every other 3D word. They are the interim home, and they fold into the 3D frame when it lands.

They work in the Beltrami-Klein ball: the unit ball of `[x, y, z]`, whose rim lies infinitely far away. In this model a hyperbolic straight line is an ordinary chord, and a hyperbolic plane is an ordinary flat plane. So a hyperbolic polyhedron is an ordinary mesh. `mesh(cell.points, cell.faces)` takes one, and the same `view` draws it.

The price is length. Klein coordinates are not hyperbolic lengths, and they shrink toward the rim. A hatch spacing or an isoline step over this geometry counts Klein units. A point at hyperbolic distance `R` from the centre of the ball sits at Klein radius `tanh R`, so `Math.atanh` of a radius reads a true distance back.

`honeycomb(p, q, r, { depth })` gives the regular cell with `r` of them around every edge, and one point map for each copy of it, the identity first. Four symbols have a compact cell in hyperbolic space: `{4, 3, 5}`, `{5, 3, 4}`, `{3, 5, 3}` and `{5, 3, 5}`. Every other one refuses by name, and it names the geometry it belongs to. `{4, 3, 4}` is Euclidean and `{3, 3, 5}` is spherical. The copies are found by reflection in the walls of the cell, out to `depth` generations. The copies at odd generations turn space over, because a reflection does.

`observer(eye, target, { up })` is the point map that moves `eye` to the centre of the ball and points `target` along `+Y`. The Klein model is true to angle at its centre. The picture the observer takes there has the angles of hyperbolic space itself. The sketch maps the scene through it and then takes `perspective({ eye: [0, 0, 0], target: [0, 1, 0] })`. A placement is a point map too, so one pass over the points does both.

`geodesic3(a, b, { count })` samples the chord between two points evenly in hyperbolic length. Two points draw the line; ask for samples when something is measured or carried along it.

A honeycomb fills space. From inside a cell, solid walls would hide every other cell, so the two drawings below take each cell as its edges. `polyline` makes a wire, and a wire hides nothing. Stand outside the ball, and `mesh(cell.points, cell.faces)` gives solid cells for the hidden-line engine to work on.

Below, the observer stands in one cube of the `{4, 3, 5}` honeycomb and looks at a wall. Five cubes meet around every edge, and the right angles of a Euclidean cube become 72 degrees. A view this wide reaches past its own frame, so the callback keeps the lines the frame holds.

```ts live
import { sketchAsync, strokes, pen, mm } from 'occlude';
import { polyline, view, perspective, honeycomb, observer, geodesic3 } from 'occlude/3d';

export default sketchAsync({ aspect: [1, 1], pens: {
  ink: pen({ width: mm(0.22), color: '#18202A' }),
} }, async () => {
  const { cell, placements } = honeycomb(4, 3, 5, { depth: 4 });
  // Every edge of the cell once: a closed cell runs each edge both ways.
  const edges = cell.faces.flatMap((f) => f.map((a, i) => [a, f[(i + 1) % f.length]]).filter(([a, b]) => a < b));
  // A little off the centre of one cube, looking at a wall.
  const eye = observer([0.05, -0.08, 0.1], [0.8, 0, 0]);
  const name = (p) => p.map((v) => Math.round(v * 1e6)).join(',');
  const drawn = new Set();
  const wires = [];
  for (const place of placements) {
    const here = cell.points.map(place);
    const seen = here.map(eye);
    // Depth counts reflections; a hyperbolic radius is the honest cut.
    // The eye sits at the centre of the ball, and a point at hyperbolic
    // distance R from the centre sits at Klein radius tanh R.
    const middle = eye(place([0, 0, 0]));
    if (Math.atanh(Math.hypot(middle[0], middle[1], middle[2])) > 3) continue;
    for (const [a, b] of edges) {
      const id = [name(here[a]), name(here[b])].sort().join('|');
      if (drawn.has(id)) continue;
      drawn.add(id);
      wires.push(polyline(geodesic3(seen[a], seen[b], { count: 24 })));
    }
  }
  return view(wires, { camera: perspective({ eye: [0, 0, 0], target: [0, 1, 0], fovDegrees: 100, near: 0.01 }), stroke: 'ink' }, (lines) => {
    const r = lines.visible.source.frame.paper;
    const held = (p) => p[0] >= r.x && p[0] <= r.x + r.width && p[1] >= r.y && p[1] <= r.y + r.height;
    return strokes(lines.visible.filter((c) => held(c.a) && held(c.b)), { stroke: 'ink' });
  });
});
```

The `{5, 3, 4}` honeycomb fills space with right-angled dodecahedra, four around every edge. The observer stands a little toward one corner of a cell and looks at the wall across from it. An `up` tilted off the world's own rolls the picture. The heavier pen draws the cell the observer stands in, so the eye finds the room. Its far wall is the small pentagon at the middle, and the near edges of the room run out to the corners of the frame.

```ts live
import { sketchAsync, strokes, pen, mm } from 'occlude';
import { polyline, view, perspective, honeycomb, observer, geodesic3 } from 'occlude/3d';

export default sketchAsync({ aspect: [1, 1], pens: {
  ink: pen({ width: mm(0.18), color: '#46505C' }),
  room: pen({ width: mm(0.38), color: '#18202A' }),
} }, async () => {
  const { cell, placements } = honeycomb(5, 3, 4, { depth: 2 });
  const edges = cell.faces.flatMap((f) => f.map((a, i) => [a, f[(i + 1) % f.length]]).filter(([a, b]) => a < b));
  const middle = (f) => [0, 1, 2].map((k) => f.reduce((s, i) => s + cell.points[i][k], 0) / f.length);
  const corner = cell.points[0];
  const toward = (p) => p[0] * corner[0] + p[1] * corner[1] + p[2] * corner[2];
  const wall = cell.faces.map(middle).reduce((a, b) => (toward(a) < toward(b) ? a : b));
  const eye = observer(corner.map((v) => v * 0.15), wall, { up: [0.26, 0, 0.97] });
  const name = (p) => p.map((v) => Math.round(v * 1e6)).join(',');
  const drawn = new Set();
  const wires = [];
  // The identity comes first, so the room the observer stands in is the
  // first cell drawn, and it takes the heavier pen.
  placements.forEach((place, k) => {
    const here = cell.points.map(place);
    const seen = here.map(eye);
    for (const [a, b] of edges) {
      const id = [name(here[a]), name(here[b])].sort().join('|');
      if (drawn.has(id)) continue;
      drawn.add(id);
      wires.push(polyline(geodesic3(seen[a], seen[b], { count: 24 }), k === 0 ? { stroke: 'room' } : {}));
    }
  });
  return view(wires, { camera: perspective({ eye: [0, 0, 0], target: [0, 1, 0], fovDegrees: 100, near: 0.005 }), stroke: 'ink' }, (lines) => {
    const r = lines.visible.source.frame.paper;
    const held = (c) => [c.a, c.b].every((p) => p[0] >= r.x && p[0] <= r.x + r.width && p[1] >= r.y && p[1] <= r.y + r.height);
    return [
      strokes(lines.visible.filter((c) => held(c) && c.feature.stroke !== 'room'), { stroke: 'ink' }),
      strokes(lines.visible.filter((c) => held(c) && c.feature.stroke === 'room'), { stroke: 'room' }),
    ];
  });
});
```
