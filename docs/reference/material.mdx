---
title: Material
description: Points with columns and an edge list. The editable form of geometry.
---

A material is a set of vertices and an edge list. Each vertex has `x`, `y` and any number of named columns. A ring, an open chain, a tree and a cloud of loose points are all materials. Every operation returns a new material and changes nothing, so you can keep any state and come back to it.

:::note
A row index belongs to one state. After a step adds or removes vertices, the rows get new numbers. Hold a value, not an index.
:::

## material()

<include>/_sig/material.mdx</include>

Builds a material from positions. Give pairs or `{ x, y }` objects. The points have no edges unless you give `edges`, as pairs of row numbers. Every other option is a column. A number sets the value on every row. An array sets one value for each row. A point that carries a `w` becomes a column too.

```ts live
import { sketch, circle, strokes, material } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const m = material([[12, 30], [50, 12], [88, 30], [50, 88]], { edges: [[0, 1], [1, 2], [0, 3], [2, 3]], weight: [1.5, 3, 1.5, 4] });
  return [strokes(m), m.points.map((p) => circle(p, p.weight, { pen: 'stabilo-88-blue' }))];
});
```

## curve()

<include>/_sig/curve.mdx</include>

Builds one chain from positions, in the order given. `closed: true` makes a ring. The other options are columns, as in `material()`.

```ts live
import { sketch, strokes, curve } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const zig = t.times(9, (k) => [10 + k * 10, k % 2 ? 20 : 45]);
  return [strokes(curve(zig, { closed: false })), strokes(curve([[15, 65], [85, 65], [50, 92]], { closed: true }))];
});
```

## t.material()

<include>/_sig/Toolkit.material.mdx</include>

Reads shapes as material and keeps their own vertices: the four corners of a rectangle, the points of a path. A curved part becomes segments, with `tolerance` (0.05 mm by default) as the largest error. A closed outline becomes a ring, an open one a chain. Several shapes become several outlines in one material. Nothing joins them.

```ts live
import { sketch, rect, ngon, strokes, circle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const m = t.material(rect(8, 30, 38, 40), ngon(72, 50, 6, 24));
  return [strokes(m), m.points.map((p) => circle(p, 1.2, { pen: 'stabilo-88-blue' }))];
});
```

## t.sample()

<include>/_sig/Toolkit.sample.3.mdx</include>

Reads a shape as material with new vertices, spaced evenly along the outline by arc length. Give `count` or `spacing`. The samples need not land on the shape's corners. Use `t.material()` to keep the corners, and `t.sample()` to get even spacing.

```ts live
import { sketch, rect, circle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const m = t.sample(rect(12, 20, 76, 60), { count: 28 });
  return [rect(12, 20, 76, 60), m.points.map((p) => circle(p, 1.4, { pen: 'stabilo-88-blue' }))];
});
```

## append()

<include>/_sig/append.mdx</include>

Puts several materials in one, in the order given. The rows of each one come after the rows of the one before. The edges get new row numbers. All of them must have the same columns. If one has a column that another does not, `fill` gives the value that the other gets.

```ts live
import { sketch, strokes, curve, append, connect, circle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const parts = t.times(4, (k) => curve([[12 + k * 22, 12], [24 + k * 22, 88]], { closed: false }));
  const one = append(...parts);
  return [strokes(one), strokes(connect.nearest(one, { count: 1 }), { pen: 'stabilo-88-blue' }), one.points.map((p) => circle(p, 1.2))];
});
```

`pts` is what a `stroke` wants, and `n` is what turns a row number into a fraction of the way round.

```ts live
import { sketch, stroke, circle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 38), { count: 26 });
  return [stroke([...ring.pts, ring.pts[0]]), ring.points.map((p) => circle(p, 0.5 + (3.4 * p.index) / ring.n, { pen: 'stabilo-88-blue' }))];
});
```

## curves()

<include>/_sig/Material.curves.mdx</include>

The chains of the material, each one once, as records that `stroke` and `polygon` accept. A chain runs from an end or a junction to the next one. `strokes(m)` is the same walk with the drawing done for you.

```ts live
import { sketch, stroke, material } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const y = material([[10, 12], [50, 50], [90, 12], [50, 92]], { edges: [[0, 1], [1, 2], [1, 3]] });
  return y.curves().map((c, i) => stroke(c, { pen: i === 1 ? 'stabilo-88-blue' : undefined }));
});
```

## What a geometry value can say

A value answers `contours()` for areas, `curves()` for chains, and `points` for positions. A consumer asks for the one it needs, and it refuses a value that cannot answer, by name.

A shape is not geometry until the toolkit lowers it. Every word on `t` takes a shape. The plain import takes geometry. `t.distanceTo(circle(...))` works and `distanceTo(circle(...))` does not, because a shape needs the paper, the units and its own transform before it has points.

A shape enters the point world through two doors only. `t.material(shape)` keeps the boundary's own vertices. `t.sample(shape, { count })` redistributes along it by arc length. `connect.*`, `voronoi` and `t.quadtree` take points, so give them the material one of those doors made.

| value | answers |
| --- | --- |
| material | `contours()`, `curves()`, `points` |
| point selection | `points`, `curves()` |
| edge selection | `points`, `curves()` |
| face collection or face selection | `points`, `edges`, `contours()` |
| one face | `points`, `edges`, `contours()` |
| contour records and loops | themselves |

One material, three answers. From the left, `polygon` reads its `contours()`, `strokes` its `curves()`, and `dots` its `points`.

```ts live
import { sketch, circle, polygon, strokes, dots, group, fill, pen, mm } from 'occlude';

export default sketch({ aspect: [3, 1], pens: { ink: pen({ width: mm(0.25), color: '#23252B' }), tap: pen({ width: mm(1.4), color: '#23252B' }) } }, (t) => {
  const m = t.sample(circle(50, 50, 38), { count: 16 });
  return [
    polygon(m, { fill: fill('hatch', { angle: 45, spacing: mm(1.4) }), stroke: false }),
    group({ translate: [100, 0] }, strokes(m)),
    group({ translate: [200, 0] }, dots(m, { pen: 'tap' })),
  ];
});
```

## What a point or an edge is, across states

Every vertex and every edge has an `id` for as long as it exists. An id is opaque: you cannot do arithmetic with it, and it is equal only to itself. It is never reused.

New geometry mints new ids. A step that moves or sets keeps them. A split retires the edge it cut and gives both halves ids of their own, so `edgeOf(parentId)` finds nothing afterwards.

A selection can then outlive the state that made it. `sel.in(state)` reads a selection against a later state and drops the members that are gone. `sel.has(view)` asks by identity, so a vertex you kept from an earlier step is the same vertex. A step verb takes a selection from an earlier state and finds the rows itself.

Store an id in an ordinary column and look it up later with `m.pointOf(id)` or `m.edgeOf(id)`. `m.points.at(row)` and `m.edges.at(row)` ask the same question by position in one state. An id and a row are both numbers. The two have different names, and neither guesses.

Here the sketch splits a ring of twelve vertices three times, then pushes it about. The ring ends with ninety-six rows, in a new order. Three vertices held from the first state still answer in the last one. An id kept in a plain variable finds its vertex again.

```ts live
import { sketch, strokes, circle } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 3 }, (t) => {
  const ring = t.sample(circle(50, 50, 34), { count: 12 });
  const held = ring.points.filter((p) => p.index % 4 === 0);
  const anchorId = ring.points.at(2).id;
  const grown = ring.steps(
    3,
    (cur, next) => next.splitEdges(cur.edges, { at: 0.5 }),
    (cur, next) => next.move(cur.points, (p) => [t.noise(p.x / 16, p.y / 16) * 5, t.noise(p.y / 16, p.x / 16) * 5]),
  );
  const anchor = grown.pointOf(anchorId);
  return [
    strokes(grown),
    held.in(grown).map((p) => circle(p, 2.5, { pen: 'stabilo-88-blue' })),
    circle(anchor, 4.5),
  ];
});
```

## attribute() · attributes()

<include>/_sig/Material.attribute.mdx</include>
<include>/_sig/Material.attributes.mdx</include>

Adds a column to every vertex and returns the new material. The value is a number, or a function of the vertex. `attributes` adds several columns at once. Each function reads the material as it was, so a new column never sees another new column. A second call sees the first call's columns, because by then they are part of the material. `transfer` says what a column does at a new vertex, after a split or a resample. `'interpolate'` (the default) blends the two values. `'nearest'` copies the nearer one.

```ts live
import { sketch, strokes, circle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t
    .sample(circle(50, 50, 40), { count: 36 })
    .attribute('lift', (p) => (p.y < 50 ? 1 : 0))
    .attributes({ reach: (p) => 0.6 + p.x / 40, side: (p) => (p.x < 50 ? 0 : 1) });
  return [strokes(ring), ring.points.filter((p) => p.lift === 1).map((p) => circle(p, p.reach, { pen: p.side === 1 ? 'stabilo-88-blue' : undefined }))];
});
```

## edgeAttribute() · edgeAttributes()

<include>/_sig/Material.edgeAttribute.mdx</include>
<include>/_sig/Material.edgeAttributes.mdx</include>

The same for edges: one value for each edge, read from the edge view. `transfer` for an edge column is `'copy'` (the default) or `'distribute'`. `'distribute'` shares a quantity over the parts of a split edge.

```ts live
import { sketch, strokes, circle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t
    .sample(circle(50, 50, 40), { count: 40 })
    .edgeAttribute('long', (e) => (e.a.x > 50 ? 1 : 0))
    .edgeAttributes({ high: (e) => (e.a.y < 50 ? 1 : 0) });
  return [
    strokes(ring.edges.filter((e) => e.attrs.long === 1 && e.attrs.high === 1), { pen: 'stabilo-88-green' }),
    strokes(ring.edges.filter((e) => e.attrs.long === 1 && e.attrs.high === 0), { pen: 'stabilo-88-blue' }),
    strokes(ring.edges.filter((e) => e.attrs.long === 0)),
  ];
});
```

## smooth()

<include>/_sig/Material.smooth.mdx</include>

Replaces a column by the mean of itself and its neighbours, `steps` times. It finds the domain from the name. A point column averages over the points an edge joins to it. An edge column averages over the edges that share a vertex with it. `mesh.smooth` is the same word in 3D, with the same option.

A tone that comes off an image carries speckle, and speckle in a density column gives banding on paper. `force.relax` smooths positions. This smooths a value and moves nothing, so every id and every position survives. A row with no neighbours is the mean of itself and keeps what it had.

Below, the mark size is the column. The left cloud takes its tone straight from a noisy field. `t.noise` runs from -1 to 1. The sketch centres and scales the tone, so every mark keeps a positive size. The right cloud is the same tone after six passes: the noise's own shape stays, and the speckle goes.

```ts live
import { sketch, circle, group, rect, connect } from 'occlude';

export default sketch({ aspect: [2, 1], seed: 4 }, (t) => {
  const b = t.bounds();
  const half = rect(0, 0, 0.47 * b.w, b.h);
  const cloud = connect.nearest(t.scatter({ spacing: 0.05 * b.h, within: half }), { count: 3 })
    .attribute('tone', (p) => 0.55 + 0.35 * t.noise(p.x / 20, p.y / 20) + 0.6 * (t.rnd() - 0.5));
  const marks = (m) => m.points.map((p) => circle(p, 0.004 * b.h + 0.024 * b.h * Math.max(0, p.tone)));
  return [marks(cloud), group({ translate: [0.53 * b.w, 0] }, marks(cloud.smooth('tone', { steps: 6 })))];
});
```

## What keeps a column

A column belongs to the material that declares it. An operation that makes a new material decides what to carry. This table is what the code does today.

| operation | point columns | edge columns | transfer policies |
|---|---|---|---|
| `warp`, `snap`, `resample`, `trails`, `planarize`, `append`, `withEdges`, `steps` | kept | kept | kept |
| `oscillate` | kept | kept, and each new span reads the source edge it starts on | kept |
| `thicken`, `envelope`, `interlace` | dropped | dropped | dropped |

The third row makes new vertices that come from no one source row. `thicken` can trace an output vertex back: `{ point: (event) => … }` gets every source candidate for that vertex, and what you return becomes the row. `oscillate` refuses an edge column with the `'distribute'` policy, because the swung chain is longer than its source. To keep a column through the third row, read it off the source and set it again on the result.

Below, a ring carries a size column through `warp`. The bent ring still reads it.

```ts live
import { sketch, strokes, circle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 30), { count: 24 }).attribute('r', (p) => 0.8 + (p.index % 3));
  const bent = ring.warp({ from: [[10, 10], [90, 10], [90, 90], [10, 90]], to: [[10, 10], [90, 22], [78, 90], [22, 78]] });
  return [strokes(bent), bent.points.map((p) => circle(p, p.r, { pen: 'stabilo-88-blue' }))];
});
```

## merge()

<include>/_sig/Material.merge.mdx</include>

Resolves coincident ink. Two rectangles snapped edge to edge draw the shared wall twice, and `planarize` refuses a doubled wall. `merge` makes one vertex of every vertex at one position, and it keeps a duplicated edge once. Two collinear edges that overlap become the spans they cover, and each span holds the ink once. `tolerance` is a length in material units, and the default 0 asks for exact coincidence. An edge that nothing touches keeps its id. A span keeps the lineage of its source edge, so a face column still finds its wall.

The screen below is four columns of panes. Each pane is a rectangle of its own, so every inner wall arrives twice. A tall wall also lies along two short ones. One `merge` call resolves both. `planarize` then reads the faces, and each face takes its own hatch angle. The small panes carry the close hatch, so the screen reads as tone.

```ts live
import { sketch, strokes, polygon, fill, rect, append, mm } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const b = t.bounds();
  const cols = [[0.06, 0.32], [0.32, 0.6], [0.6, 0.78], [0.78, 0.94]];
  const rows = [4, 3, 5, 3];
  const top = 0.08 * b.h;
  const tall = 0.84 * b.h;
  const panes = cols.flatMap(([x0, x1], c) => t.times(rows[c], (k) =>
    t.material(rect(x0 * b.w, top + (k / rows[c]) * tall, (x1 - x0) * b.w, tall / rows[c]))));
  const screen = append(...panes).merge();
  const cells = screen.planarize().faces();
  const biggest = Math.max(...cells.map((f) => f.area));
  return [
    cells.map((f, i) => polygon(f, {
      stroke: false,
      fill: fill('hatch', { angle: 18 + i * 31, spacing: mm(0.5 + (2.6 * f.area) / biggest) }),
    })),
    strokes(screen),
  ];
});
```

## resample()

<include>/_sig/Material.resample.mdx</include>

Puts new vertices along each chain at even spacing by arc length. Give `spacing` or `count`, in material units. An open chain keeps both ends. A closed chain keeps its seam. A corner between two new vertices does not survive. Chains only: a junction is an error.

`where` redistributes part of the material and leaves the rest alone. The eligible region is a set of edges, so a point selection means the edges with both ends in it. Consecutive eligible edges make a **run**, and a run is what gets redistributed. A run keeps the two vertices at its ends, so the result is still one chain. `count` then applies to each run, not to the chain.

Everything outside a run comes through untouched and keeps its identity: the same point ids, the same edge ids, the same lineage. A new vertex inside a run gets a new id. A new edge takes the lineage of the edge it came from. A split's children do the same, so a face column still finds its cells. See [where](/docs/reference/selections#where).

Below, the big rings are the eleven vertices the chain started with. Only the steep edges are eligible. The two level stretches keep their two ends and nothing else. The rises and the falls get a vertex every few millimetres.

```ts live
import { sketch, strokes, circle, curve } from 'occlude';

export default sketch({ aspect: [2, 1], seed: 2 }, (t) => {
  const b = t.bounds();
  const ridge = curve(t.times(11, (k, u) => [(0.06 + 0.88 * u) * b.w, (0.5 + 0.34 * Math.sin(u * 7)) * b.h]), { closed: false });
  const steep = ridge.edges.filter((e) => Math.abs(e.b.y - e.a.y) > 0.12 * b.h);
  const out = ridge.resample({ spacing: 0.035 * b.w, where: steep });
  return [
    strokes(out),
    out.points.map((p) => circle(p, 0.9, { pen: 'stabilo-88-blue' })),
    ridge.points.map((p) => circle(p, 2.2)),
  ];
});
```

```ts live
import { sketch, strokes, circle, curve } from 'occlude';

  const even = rough.resample({ spacing: 6 });
```

## spline()

<include>/_sig/Material.spline.mdx</include>

Draws a curve through the vertices of each chain and returns it as material. The `smooth` modifier rounds a corner off, and the line passes inside it. `spline` keeps the corner vertex and bends the line between the corners, so the positions you picked are still on the drawing.

`tension` scales the tangent at each vertex. 0 is the polyline it started from. 0.5, the default, is the ordinary curve. 1 swings wide and overshoots. `steps` is the number of samples for each source segment, 8 by default. Closure comes from the chain: a ring has no corner at its seam. An open chain takes the tangent at each end from its end segment. A chain of fewer than three vertices has no curve, so it comes through as it is. Chains only: a junction is an error.

The source vertices keep their ids, their positions and their columns. Each new vertex between them is new, and its columns come from the transfer policies. The call retires every source edge, and its children keep its lineage, so a face column still finds its cells.

Below, seven picked positions (blue), the polyline through them (fine), and its spline. The spline passes through every one of them.

```ts live
import { sketch, strokes, curve, circle } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 5 }, (t) => {
  const picked = t.times(7, (i, u) => [10 + u * 80, 50 + t.rnd(-26, 26)]);
  const crest = curve(picked, { closed: false });
  return [strokes(crest, { pen: 'pigma-005-black' }), strokes(crest.spline({ tension: 0.6 })), picked.map((p) => circle(p, 1.4, { pen: 'stabilo-88-blue' }))];
});
```

## along()

<include>/_sig/Material.along.mdx</include>

Reads stations along each chain and changes nothing. A station is plain data. It has `x` and `y`, the unit `tangent` and `normal` of the chain under it, and the `heading` in radians. It has the arc length `s`, its fraction `u`, and the point columns in `attrs`. With no option, there is one station at each vertex. Use `resample()` when the material must be even. Use `along()` to put things on it.

```ts live
import { sketch, strokes, circle, line, add, mul } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.material(circle(50, 50, 34));
  const ticks = ring.along({ spacing: 9 }).map((s) => line(s, add(s, mul(s.normal, 8))));
  return [strokes(ring), ticks];
});
```

## station.place()

<include>/_sig/Station.place.mdx</include>

Puts a drawable on a station, turned to the station's heading. `offset: [alongTangent, alongNormal]` moves it in the station's own frame. `rotate` adds degrees to the heading. `scale` comes before the rotation. A negative value mirrors.

A motif sits about the origin, as it always did. A curved space has no flat frame to turn, so `place` is a [placement](/docs/reference/geometry#placement). The station's own isometry carries the motif from the origin to the station.

```ts live
import { sketch, strokes, circle, rect } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.material(circle(50, 50, 34));
  return [strokes(ring), ring.along({ count: 14 }).map((s) => s.place(rect(-4, -2, 8, 4), { offset: [0, 7] }))];
});
```

## station.step() · station.turn() · station.toward()

<include>/_sig/Station.step.mdx</include>
<include>/_sig/Station.turn.mdx</include>
<include>/_sig/Station.toward.mdx</include>
<include>/_sig/Toolkit.station.mdx</include>

`t.station(x, y, { heading })` starts a walk at any point. The heading is in degrees, counter-clockwise from `+x`. `t.station(point, { heading })` takes a pair or an `{ x, y }` record, so a station or a centroid goes straight in. The `heading` field of a station stays in radians, because every station verb reads it.

`station.step(distance)` gives a new station that distance along the heading. `station.turn(degrees)` gives a new station with the heading turned. `station.toward(q)` gives a new station at the same place, facing `q` along the geodesic from here to there. A `q` at this very place keeps the heading. On a sphere, a `q` exactly opposite has no one direction, and the station refuses it by name.

In the flat plane a step adds `distance · (cos h, sin h)`. In a curved space a step walks the geodesic. A closed walk there brings the walker back turned, and that turn is the holonomy. Below, five equal legs with a quarter turn between them close a pentagon of the hyperbolic plane. The blue ticks are the heading at the start and at the end.

```ts live
import { sketch, line, circle, space } from 'occlude';

export default sketch({ aspect: [1, 1], space: space.hyperbolic({ radius: 50 }) }, (t) => {
  const { cell } = t.tiling(5, 4);
  const side = t.space.distance(cell[0], cell[1]);
  let st = t.station(cell[0]).toward(cell[1]);
  const start = st;
  const legs = [];
  for (let i = 0; i < 5; i++) {
    const from = st;
    st = st.step(side);
    legs.push(line(from, st));
    if (i < 4) st = st.turn(90);
  }
  const tick = (s) => line(s, s.step(8), { pen: 'stabilo-88-blue' });
  return [circle(t.space.center, 400), legs, tick(start), tick(st)];
});
```
