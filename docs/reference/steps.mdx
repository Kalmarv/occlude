`steps` runs a rule against a material and returns the material after `n` iterations. The rule reads a frozen state and asks for edits on a copy. The step applies the edits together. Then the next iteration starts. Nothing changes while the rule reads.

## steps()

<include>/_sig/Material.steps.mdx</include>

The rule is `(prev, next, k) => …`: `prev` is the current state, `next` collects the edits, `k` is the iteration. The shorthand `{ move, set }` applies one move or one column write to every point. Several rules become passes: each pass reads the state the pass before it produced. An ARRAY of rules is one batch instead: every rule in it matches the same frozen state. `{ every: m }` keeps the initial state, every m-th state and the last one on the result's `history`.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 30), { count: 60 });
  const grown = ring.steps(8, { move: (p) => [(p.x - 50) * 0.06, (p.y - 50) * 0.06 * (1 + 0.5 * Math.sin(p.index))] }, { every: 2 });
  return grown.history.map((h) => strokes(h));
});
```

## One batch or several passes

`steps(n, [a, b])` is ONE batch. Both passes read the same frozen state. A point that `a` moves is still where it was when `b` looks at it. `steps(n, a, b)` is two batches, and `b` reads what `a` committed.

Reading is order-free. Editing is not, and the batch rules decide it. Moves add up, so two moves commute. A later `set` overwrites an earlier one. A later `connect` on a pair an earlier pass already made changes nothing. New points keep the order the passes asked for them.

Some edits in one batch cannot land. The step does not fail. It drops each of these edits and gives a reason. The order of the batch does not change what it drops. A removal wins over a move, a write, a split or a join on that point. A disconnection wins over a split or a write on that edge.

| Reason | The step drops the edit when |
|---|---|
| `gone` | a reference names nothing in this state: a removed point, a split edge, an id of another material, or a new point that did not land |
| `self` | a `connect` joins a point to itself |
| `already` | the state is already what the edit asks: a joined pair, a second `remove` of a point, a second `disconnect` of an edge, or the same new point two times in the list |
| `removed` | the edit touches a point that the batch removes |
| `disconnected` | the edit touches an edge that the batch disconnects |
| `conflict` | two splits at one place on an edge give different values. The step makes one cut with the values that it inherits |
| `not-finite` | a move, a position, a value or an `at` is not a finite number |

`m.dropped` on the result lists each dropped edit, with its reason and its step `k`.

Below, rule `a` moves a ring to the right, and rule `b` moves down every point right of x = 30. At the top, one batch: `b` sees the ring where it was, so only its right side drops. At the bottom, two passes: `b` sees the moved ring, so all of it drops. The fine rings are the start.

```ts live
import { sketch, strokes, circle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const a = (cur, next) => next.move(cur.points, [30, 0]);
  const b = (cur, next) => next.move(cur.points.filter((p) => p.x > 30), [0, 10]);
  const ring = (y) => t.sample(circle(24, y, 14), { count: 48 });
  return [
    strokes(ring(26), { pen: 'pigma-005-black' }), strokes(ring(26).steps(1, [a, b])),
    strokes(ring(68), { pen: 'pigma-005-black' }), strokes(ring(68).steps(1, a, b), { pen: 'stabilo-88-blue' }),
  ];
});
```

## next.move()

<include>/_sig/Next.move.mdx</include>

Moves the selected points by a vector, or by one vector for each point from a callback. Several moves on one point add up. A move is a step in the [space](/docs/reference/geometry) of the material. So in a curved sketch, the point walks the sum of its moves along a geodesic.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 32), { count: 48 });
  const wavy = ring.steps(1, (cur, next) => next.move(cur.points, (p) => [0, Math.sin(p.x / 4) * 8]));
  return [strokes(ring, { pen: 'pigma-005-black' }), strokes(wavy, { pen: 'stabilo-88-blue' })];
});
```

## next.set() · next.setEdges()

<include>/_sig/Next.set.mdx</include>

Writes columns on the selected points or edges. Give an object, or a callback that returns one object for each row. A column must exist already: declare it with `attribute` first.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {

  const aged = ring.steps(5, (cur, next) => next.set(cur.points.filter((p) => p.x > 50), (p) => ({ age: p.age + 1 })));
  return [strokes(aged), aged.points.map((p) => circle(p, 0.5 + p.age * 0.5, { pen: 'stabilo-88-blue' }))];
});
```

## next.extrude()

<include>/_sig/Next.extrude.mdx</include>

Adds children to the selected points and joins each child to its parent. The callback returns a child `{ position, attributes }`, a list of them, or `[]` for none. A child can also be `{ to }`. That joins the parent to an existing point instead. With `inherit: true`, a child starts from its parent's columns. A new point must give every declared column.

```ts live
import { sketch, strokes, material, add, mul, fromAngle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const seed = material([[50, 92]], { heading: -Math.PI / 2, tip: 1 });
  const tree = seed.steps(26, (cur, next, k) => {
    const tips = cur.points.filter((p) => p.tip === 1 && p.y > 10 && p.x > 10 && p.x < 90);
    next.extrude(tips, (p) => {
      const fork = k % 5 === 0 ? [p.heading - 0.5, p.heading + 0.5] : [p.heading + t.noise(p.x / 20, p.y / 20) * 0.4];
      return fork.map((h) => ({ position: add(p, mul(fromAngle(h), 3.2)), attributes: { heading: h, tip: 1 } }));
    });
    next.set(tips, { tip: 0 });
  });
  return strokes(tree);
});
```

## next.split() · next.splitEdges()

<include>/_sig/Next.split.mdx</include>
<include>/_sig/Next.splitEdges.mdx</include>

Replaces an edge with two edges through a new vertex, at the fraction `at` along it (0.5 by default). The new vertex gets its columns by each column's transfer rule, and `point` overrides them. `splitEdges` does it for a selection. `split` returns its record, and the record names the new vertex in the same batch.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 34), { count: 8 });
  const finer = ring.steps(3, (cur, next) => next.splitEdges(cur.edges.filter((e) => e.length > 12)));
  return [strokes(finer), finer.points.map((p) => circle(p, 1, { pen: 'stabilo-88-blue' }))];
});
```

## next.replace()

<include>/_sig/Next.replace.mdx</include>

Swap every selected edge for a motif. The edge goes, and the motif's chain takes its place between the same two points. `replace` reads the motif in its own frame. That frame runs along the line from its first point to its last, and across it. One motif rides an edge of any length at any angle. Point columns interpolate and edge columns inherit, exactly as a split's children do.

An L-system is exactly this substitution, over and over. A Koch curve is one motif and four steps.

```ts live
import { sketch, strokes, material, circle } from 'occlude';

export default sketch({ aspect: [1, 1], margin: 6 }, (t) => {
  const b = t.bounds();
  const h = Math.sqrt(3) / 6;
  const motif = material([[0, 0], [1 / 3, 0], [0.5, h], [2 / 3, 0], [1, 0]], { edges: [[0, 1], [1, 2], [2, 3], [3, 4]] });
  const seed = t.sample(circle(b.w / 2, b.h * 0.56, b.w * 0.42), { count: 3 });
  const flake = seed.steps(4, (cur, next) => next.replace(cur.edges, motif, { flip: true }));
  return strokes(flake.curves());
});
```

:::note
A motif is ONE open chain, read from its edges and not from its row order. Nothing but the build order decides a material's rows. A motif with the right points in the wrong order would draw something else. `flip` mirrors it across the edge. The callback sees the step, so alternating on the step turns the curve inward and outward by turns. The seed's winding decides the outward side.
:::

## next.connect() · next.disconnect()

<include>/_sig/Next.connect.mdx</include>
<include>/_sig/Next.disconnect.mdx</include>

`connect` adds one edge between two references: vertex views, point ids, or the records of new points in this batch. A pair that is already joined stays as it is. `disconnect` removes edges and keeps their points.

```ts live
import { sketch, circle, strokes, distance } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const cloud = t.scatter({ spacing: 12 });
  const joined = cloud.steps(1, (cur, next) => {
    for (const [p, q] of cur.points.pairs(cur.points, (a, b) => distance(a, b) < 16, { radius: 16 })) next.connect(p, q);
  });
  const trimmed = joined.steps(1, (cur, next) => next.disconnect(cur.edges.filter((e) => e.a.x < 50 && e.b.x < 50)));
  return [strokes(trimmed), cloud.points.map((p) => circle(p, 0.8))];
});
```

## next.remove() · next.addPoint()

<include>/_sig/Next.remove.mdx</include>
<include>/_sig/Next.addPoint.mdx</include>

`remove` deletes points and the edges that touch them. The neighbours of a removed point are not joined. `addPoint` adds a loose point and returns its record, and `connect` accepts that record in the same batch.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 34), { count: 36 });
  const gapped = ring.steps(1, (cur, next) => {
    next.remove(cur.points.filter((p) => p.index % 9 === 0));
    const h = next.addPoint([50, 50], {});
    for (const p of cur.points.filter((p) => p.index % 9 === 4)) next.connect(p, h);
  });
  return strokes(gapped);
});
```

## next.edits

<include>/_sig/Next.edits.mdx</include>

A batch is a list of records. Each edit adds records to `next.edits`, and the step applies the list when the pass ends. A record is plain data, for example `{ op: 'connect', a, b }`. The compound edits add the simple records: `extrude` adds `addPoint` and `connect`, and `splitEdges` adds one `split` for each edge. A pass can return a list, and then that list is the batch. In `steps(n, [rule, stage])`, `stage` reads the records of `rule` and returns a changed list. `m.steps(1, () => list)` applies a list that you keep.

A record names a point by a vertex, by its `id`, or by a new point's record from the same batch. A number is always an id, and never a row. To name a row, use `cur.points.at(row)`.

| `op` | Fields |
|---|---|
| `move` | `point`, `by` |
| `set` | `point`, `attrs` |
| `setEdge` | `edge`, `attrs` |
| `setFace` | `face` (the key of the face), `attrs` |
| `addPoint` | `position`, `attrs` |
| `connect` | `a`, `b`, `attrs` |
| `disconnect` | `edge` |
| `remove` | `point` |
| `split` | `edge`, `at`, `point`, `edges` |

Below, a ring grows by the drift of Anders Hoff. At each step, a random point gets a child, and two random points join. The second pass in the list is an error process. It sends one `connect` in twenty to the first point of the ring. The black run is the drift. The blue run is the same drift with the errors. Where the two runs agree, the black covers the blue, so the blue fan is what the errors changed. A slip onto a joined pair, or onto the first point itself, drops, and the step continues.

`t.stream(name)` starts the stream again each time that you open it. So open an error stream one time, outside the rule. Here the same restart gives the two runs the same drift.

```ts live
import { sketch, strokes, circle, add, mul, fromAngle } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 11 }, (t) => {
  const ring = t.sample(circle(50, 50, 16), { count: 16 });
  const first = ring.points.at(0).id;
  const errors = t.stream('errors');
  const drift = (rng) => (cur, next) => {
    next.extrude(rng.pick(cur.points), (p) => ({ position: add(p, mul(fromAngle(rng.rnd(0, 2 * Math.PI)), 8)) }));
    next.connect(rng.pick(cur.points), rng.pick(cur.points));
  };
  const slip = (e) => (e.op === 'connect' && errors.chance(0.05) ? { ...e, b: first } : e);
  const faithful = ring.steps(220, drift(t.stream('drift')));
  const mutated = ring.steps(220, [drift(t.stream('drift')), (cur, next) => next.edits.map(slip)]);
  return [strokes(faithful), strokes(mutated, { pen: 'stabilo-88-blue' })];
});
```

## Forces

You prepare a force once, with its sources. Then it gives a vector at a point. Nothing moves until a rule calls `next.move` with it. `tension` pulls toward connected neighbours that are further than `rest`. `separation` pushes away from every source within `radius`. `attract` pulls toward sources. `drift` reads a direction from a noise function and turns slowly with the iteration, so it takes `(p, k)`. `boundary` pushes inward near the edge of an area and everywhere outside it. `vortex` turns around a centre. `field` reads a vector field. `relax` moves a vertex toward the mean of its neighbours. `boundary` reads the area's `contours()`. `separation` and `neighbours` read the sources' `points`. Here is one force alone. The black ring is the start. The blue ring is the same ring after ten steps under `separation`.

```ts live
import { sketch, circle, strokes, force, mul } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 20), { count: 40 }).attribute('lump', (p) => (p.index % 8 < 3 ? 1 : 0));
  const spread = ring.steps(10, (cur, next) => {
    const apart = force.separation(cur.points.filter((p) => p.lump === 1), { radius: 14 });
    next.move(cur.points, (p) => mul(apart(p), 0.35));
  });
  return [strokes(ring, { pen: 'pigma-005-black' }), strokes(spread, { pen: 'stabilo-88-blue' })];
});
```

`separation` also takes a radius for each vertex: `{ radius: (p) => p.r }` gives every point its own. The radius of a pair is then the sum of the two. That sum is the distance two discs need to stay clear of each other. The push peaks at that sum and fades to zero there. One grid still serves. It takes its cell from the widest radius among the sources, and each query reaches as far as its own point asks. Here the discs come from a noise field, and the run ends with none of them over another.

```ts live
import { sketch, circle, rect, force, mul } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 4 }, (t) => {
  const b = t.bounds();
  const page = t.material(rect(8, 8, b.w - 16, b.h - 16));
  const seeds = t.scatter({ spacing: 7.5 }).attribute('r', (p) => 1.5 + 6.5 * t.noise(p.x / 40, p.y / 40) ** 2);
  const packed = seeds.steps(220, (cur, next) => {
    const push = force.sum(
      force.separation(cur, { radius: (p) => p.r }),
      force.boundary(page, { radius: 9 }),
    );
    next.move(cur.points, (p) => mul(push(p), 0.25));
  });
  return packed.points.map((p) => circle(p, p.r, { pen: p.r > 4.5 ? 'stabilo-88-blue' : 'pigma-005-black' }));
});
```

Eight words, and a rule usually sums a few of them. Here a ring grows: `tension` holds the chain together, `separation` keeps it off itself, `relax` smooths it, and `drift` wanders it. A second pass splits an edge that has stretched too far, and writes the iteration onto it first. A split copies an edge column to both children. Each piece of wall keeps the step that last divided it. The drawing then finds the youngest growth.

```ts live
import { sketch, strokes, circle, force, mul } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 6 }, (t) => {
  const wander = force.drift(t.noise, { amount: 0.24, frequency: 0.05 });
  const grown = t.sample(circle(50, 50, 8), { count: 24 }).edgeAttribute('fresh', 0).steps(150, (cur, next, k) => {
    const push = force.sum(
      force.tension(cur, { rest: 1.6 }),
      force.separation(cur, { radius: 4, excludeConnected: true }),
      force.relax(cur, { amount: 0.4 }),
      wander,
    );
    next.move(cur.points, (p) => mul(push(p, k), 0.15));
  }, (cur, next, k) => {
    const stretched = cur.edges.filter((e) => e.length > 1.8 && t.chance(0.3));
    next.setEdges(stretched, { fresh: k });
    for (const e of stretched) next.split(e);
  });
  return [
    strokes(grown.edges.filter((e) => e.fresh < 135), { pen: 'pigma-005-black' }),
    strokes(grown.edges.filter((e) => e.fresh >= 135), { pen: 'stabilo-88-blue' }),
  ];
});
```

The other three forces pull toward something. `attract` pulls toward its sources. `vortex` turns around a centre. `field` reads a vector field. This field is the curl of a noise. A curl runs along the contours of the noise, and not across them. `force.sum` adds all three forces. `{ every: 1 }` keeps every state, so the sketch draws each dot's full path from `history`.

```ts live
import { sketch, stroke, circle, material, force, curl, mul } from 'occlude';

export default sketch({ aspect: [2, 1], seed: 3 }, (t) => {
  const b = t.bounds();
  const posts = [[0.28 * b.w, 0.7 * b.h], [0.74 * b.w, 0.3 * b.h]];
  const push = force.sum(
    force.attract(posts, { radius: 0.3 * b.w, strength: 1 }),
    force.vortex([0.5 * b.w, 0.5 * b.h], { strength: 1, falloff: 0.2 * b.w }),
    force.field(curl((x, y) => t.noise(x / 50, y / 50) * 8)),
  );
  const seeds = material(t.grid({ cols: 34, rows: 17 }).map((c) => [c.cx, c.cy]));
  const flown = seeds.steps(80, (cur, next) => next.move(cur.points, (p) => mul(push(p), 0.3)), { every: 1 });
  const trail = (i) => flown.history.map((h) => [h.x[i], h.y[i]]);
  return [
    seeds.points.map((p) => stroke(trail(p.index))),
    posts.map((p) => circle(p, 3, { pen: 'stabilo-88-blue' })),
  ];
});
```

## t.force

The toolkit carries the same forces as `t.force`. `t.force.boundary`, `t.force.separation` and `t.force.attract` also take a shape, because the toolkit can change a shape into geometry. The pure `force.boundary(rect(…))` refuses a shape, and its message names `t.force`. In a sketch with a `space`, the `t.force` words measure in that space. Below, dots start over all of the page, and `t.force.boundary` pushes them into a square frame.

```ts live
import { sketch, circle, rect, mul } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 3 }, (t) => {
  const frame = rect(25, 25, 50, 50);
  const held = t.scatter({ spacing: 7 }).steps(40, (cur, next) => {
    const push = t.force.sum(t.force.boundary(frame, { radius: 4 }), t.force.separation(cur, { radius: 4 }));
    next.move(cur.points, (p) => mul(push(p), 0.3));
  });
  return [rect(25, 25, 50, 50, { pen: 'stabilo-88-blue' }), held.points.map((p) => circle(p, 0.8))];
});
```

## force.sum()

<include>/_sig/force.sum.mdx</include>

Adds forces. The same rule with `separation` alone, with `boundary` alone, and with their sum, in three pens.

```ts live
import { sketch, circle, strokes, force, mul } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const box = [[10, 10], [90, 10], [90, 90], [10, 90]];
  const run = (make, pen) => strokes(t.sample(circle(50, 50, 26), { count: 40 }).steps(14, (cur, next) => next.move(cur.points, (p) => mul(make(cur)(p), 0.5))), { pen });
  return [
    run((cur) => force.separation(cur, { radius: 9, excludeConnected: true }), 'pigma-005-black'),
    run((cur) => force.boundary(box, { radius: 30 }), 'stabilo-88-blue'),
    run((cur) => force.sum(force.separation(cur, { radius: 9, excludeConnected: true }), force.boundary(box, { radius: 30 })), 'stabilo-88-green'),
    strokes(t.material(circle(50, 50, 26)), { pen: 'pigma-005-black' }),
  ];
});
```

## Your own interaction

A force of your own is a function, not a word of the library. Sum what you
want over the points within a radius. `cur.points.near(p, { radius })` is
the neighbourhood, from an index built once for the state, and a vertex is
never its own neighbour. `sumBy` adds the vectors up. To skip the points at
the other end of `p`'s edges, subtract them: `.subtract(p.adjacent)`.

```ts live
import { sketch, circle, strokes, force, sub, unit, mul, sumBy, distance } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const cloud = t.scatter({ spacing: 9 });
  const spread = cloud.steps(12, (cur, next) => {
    const repel = (p) => sumBy(cur.points.near(p, { radius: 14 }), (q) => mul(unit(sub(p, q)), 14 - distance(p, q)));
    const keep = force.boundary([[6, 6], [94, 6], [94, 94], [6, 94]], { radius: 12, strength: 3 });
    next.move(cur.points, (p) => mul(force.sum(repel, keep)(p), 0.05));
  });
  return [cloud.points.map((p) => circle(p, 0.6)), spread.points.map((p) => circle(p, 1.4, { pen: 'stabilo-88-blue' }))];
});
```
