title: Steps and forces
description: Change a material by a rule, one batch of edits at a time.
---

`steps` runs a rule against a material and returns the material after `n` iterations. The rule reads a frozen state and asks for edits on a copy. The step applies the edits together. Then the next iteration starts. Nothing changes while the rule reads.

## steps()

<include>/_sig/Material.steps.mdx</include>

The rule is `(prev, next, k) => …`: `prev` is the current state, `next` collects the edits, `k` is the iteration. The shorthand `{ move, set }` applies one move or one column write to every point. Several rules become passes: each pass reads the state the pass before it produced. An ARRAY of rules is one batch instead: every rule in it matches the same frozen state. `{ every: m }` keeps the initial state, every m-th state and the last one on the result's `history`.

:::warning
Two edits that contradict each other in one batch fail the step. Examples: remove a point and also connect it, or split an edge and also disconnect it. Moves add up, and the last write of a column wins.
:::

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 30), { count: 60 });
  const grown = ring.steps(8, { move: (p) => [(p.x - 50) * 0.06, (p.y - 50) * 0.06 * (1 + 0.5 * Math.sin(p.index))] }, { every: 2 });
  return grown.history.map((h) => strokes(h.material));
});
```

## rule.point() · rule.edge() · rule.face()

<include>/_sig/rule.point.mdx</include>
<include>/_sig/rule.edge.mdx</include>
<include>/_sig/rule.face.mdx</include>

A rule is a pattern and a replacement. The pattern picks the points, edges or faces that match, and the action says what happens to every one of them. A rule builds a `steps` rule, so `m.steps(n, rule.point(…).move(…))` is the whole story. There is no separate verb.

The actions on points are `move`, `set`, `extrude`, `connect` and `remove`. On edges they are `split`, `set`, `remove` and `replace`. On faces they are `set` and `move`.

```ts live
import { sketch, strokes, material, rule } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  // The Koch generator: a bump across the middle third of any edge.
  const h = Math.sqrt(3) / 6;
  const motif = material([[0, 0], [1 / 3, 0], [0.5, h], [2 / 3, 0], [1, 0]], { edges: [[0, 1], [1, 2], [2, 3], [3, 4]] });
  // The same rule, three times over, at three step counts.
  return [1, 3, 5].map((n, row) => {
    const y = 35 + row * 30;
    const seed = material([[15, y], [85, y]], { edges: [[0, 1]] });
    return strokes(seed.steps(n, rule.edge().replace(motif, { flip: true })).curves());
  });
});
```

:::note
`rule` is a plain import and has no seed of its own. Put a chance in the pattern, where it runs once for each row: `rule.edge((e) => t.chance(0.3)).split()`. A seeded stream lives on the toolkit.
:::

## One batch or several passes

`steps(n, [a, b])` is ONE batch. Both rules match the same frozen state. A point that `a` moves is still where it was when `b` looks at it. `steps(n, a, b)` is two passes, and `b` reads what `a` committed.

Matching is order-free. Editing is not, and the batch rules decide it. Moves add up, so two move rules commute. A later `set` overwrites an earlier one. A later `connect` on a pair an earlier rule already made changes nothing, and its edge attributes go with it. New points keep the order the rules asked for them, and row order is visible in `p.index` and in plot order.

```ts live
import { sketch, strokes, circle, rule, mul, sub } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 2 }, (t) => {
  const ring = t.sample(circle(50, 50, 26), { count: 90 });
  const grown = ring.steps(26, [
    rule.point().move((p) => mul(sub(p, [50, 50]), 0.012)),
    rule.edge((e) => e.length > 2.2).split(),
  ]);
  return strokes(grown.curves());
});
```

## A rule in three dimensions

A rule that only moves or writes runs in either world. Build it once and hand it to a material's `steps` or to a mesh's. `rule.point()` has `extrude`, `connect` and `remove`. `rule.edge()` has `split`, `remove` and `replace`. These change topology, and a mesh edit batch has none, so they belong to the flat world. `rule.face().set()` runs the other way: only a mesh stores face columns.

:::warning
A mesh stores its faces, and they own attribute columns. `rule.face().set()` writes those columns. A material computes a face from its points and edges every time, and that face owns no columns. `rule.face().set()` on a material says so and stops.
:::

## next.move()

<include>/_sig/Next.move.mdx</include>

Moves the selected points by a vector, or by one vector for each point from a callback. Several moves on one point add up.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 32), { count: 48 });
  const wavy = ring.steps(1, (cur, next) => next.move(cur.points, (p) => [0, Math.sin(p.x / 4) * 8]));
  return [strokes(ring, { pen: 'pigma-005-black' }), strokes(wavy, { pen: 'stabilo-88-blue' })];
});
```

## next.set() · next.setEdges()

<include>/_sig/Next.set.mdx</include>
<include>/_sig/Next.setEdges.mdx</include>

Writes columns on the selected points or edges. Give an object, or a callback that returns one object for each row. A column must exist already: declare it with `attribute` first.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 34), { count: 30 }).attribute('age', 0);
  const aged = ring.steps(5, (cur, next) => next.set(cur.points.filter((p) => p.x > 50), (p) => ({ age: p.age + 1 })));
  return [strokes(aged), aged.points.map((p) => circle(p.x, p.y, 0.5 + p.age * 0.5, { pen: 'stabilo-88-blue' }))];
});
```

## next.extrude()

<include>/_sig/Next.extrude.mdx</include>

Adds children to the selected points and joins each child to its parent. The callback returns a child `{ position, attributes }`, a list of them, or `[]` for none. A child can also be `{ to }`. That joins the parent to an existing point instead. With `inherit: true`, a child starts from its parent's columns. A new point must give every declared column.

```ts live
import { sketch, strokes, material, add, mul, fromAngle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const seed = material([[50, 92]], { heading: -Math.PI / 2, tip: 1 });
  const tree = seed.steps(26, (cur, next, k) => {
    const tips = cur.points.filter((p) => p.tip === 1 && p.y > 10 && p.x > 10 && p.x < 90);
    next.extrude(tips, (p) => {
      const fork = k % 5 === 0 ? [p.heading - 0.5, p.heading + 0.5] : [p.heading + t.noise(p.x / 20, p.y / 20) * 0.4];
      return fork.map((h) => ({ position: add(p, mul(fromAngle(h), 3.2)), attributes: { heading: h, tip: 1 } }));
    });
    next.set(tips, { tip: 0 });
  });
  return strokes(tree);
});
```

## next.split() · next.splitEdges()

<include>/_sig/Next.split.mdx</include>
<include>/_sig/Next.splitEdges.mdx</include>

Replaces an edge with two edges through a new vertex, at the fraction `at` along it (0.5 by default). The new vertex gets its columns by each column's transfer rule, and `point` overrides them. `splitEdges` does it for a selection. `split` returns a reference to the new vertex for use in the same batch.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 34), { count: 8 });
  const finer = ring.steps(3, (cur, next) => next.splitEdges(cur.edges.filter((e) => e.length > 12)));
  return [strokes(finer), finer.points.map((p) => circle(p.x, p.y, 1, { pen: 'stabilo-88-blue' }))];
});
```

## next.connect() · next.disconnect()

<include>/_sig/Next.connect.mdx</include>
<include>/_sig/Next.disconnect.mdx</include>

`connect` adds one edge between two references: rows, vertex views, or handles from this batch. A pair that is already joined stays as it is. `disconnect` removes edges and keeps their points.

```ts live
import { sketch, circle, strokes, distance } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const cloud = t.scatter({ spacing: 12 });
  const joined = cloud.steps(1, (cur, next) => {
    for (const p of cur.points) for (const q of cur.points) if (q.index > p.index && distance(p, q) < 16) next.connect(p, q);
  });
  const trimmed = joined.steps(1, (cur, next) => next.disconnect(cur.edges.filter((e) => e.a.x < 50 && e.b.x < 50)));
  return [strokes(trimmed), cloud.points.map((p) => circle(p.x, p.y, 0.8))];
});
```

## next.remove() · next.addPoint()

<include>/_sig/Next.remove.mdx</include>
<include>/_sig/Next.addPoint.mdx</include>

`remove` deletes points and the edges that touch them. The neighbours of a removed point are not joined. `addPoint` adds a loose point and returns a handle that `connect` accepts in the same batch.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 34), { count: 36 });
  const gapped = ring.steps(1, (cur, next) => {
    next.remove(cur.points.filter((p) => p.index % 9 === 0));
    const h = next.addPoint([50, 50], {});
    for (const p of cur.points.filter((p) => p.index % 9 === 4)) next.connect(p, h);
  });
  return strokes(gapped);
});
```

## Forces

<include>/_sig/force.tension.mdx</include>
<include>/_sig/force.separation.mdx</include>
<include>/_sig/force.attract.mdx</include>
<include>/_sig/force.drift.mdx</include>
<include>/_sig/force.boundary.mdx</include>
<include>/_sig/force.vortex.mdx</include>
<include>/_sig/force.field.mdx</include>
<include>/_sig/force.relax.mdx</include>

You prepare a force once, with its sources. Then it gives a vector at a point. Nothing moves until a rule calls `next.move` with it. `tension` pulls toward connected neighbours that are further than `rest`. `separation` pushes away from every source within `radius`. `attract` pulls toward sources. `drift` reads a direction from a noise function and turns slowly with the iteration, so it takes `(p, k)`. `boundary` pushes inward near the edge of an area and everywhere outside it. `vortex` turns around a centre. `field` reads a vector field. `relax` moves a vertex toward the mean of its neighbours. Here is one force alone. The black ring is the start. The blue ring is the same ring after ten steps under `separation`.

```ts live
import { sketch, circle, strokes, force, mul } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 20), { count: 40 }).attribute('lump', (p) => (p.index % 8 < 3 ? 1 : 0));
  const spread = ring.steps(10, (cur, next) => {
    const apart = force.separation(cur.points.filter((p) => p.lump === 1), { radius: 14 });
    next.move(cur.points, (p) => mul(apart(p), 0.35));
  });
  return [strokes(ring, { pen: 'pigma-005-black' }), strokes(spread, { pen: 'stabilo-88-blue' })];
});
```

## force.sum()

<include>/_sig/force.sum.mdx</include>

Adds forces. The same rule with `separation` alone, with `boundary` alone, and with their sum, in three pens.

```ts live
import { sketch, circle, strokes, force, mul } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const box = [[10, 10], [90, 10], [90, 90], [10, 90]];
  const run = (make, pen) => strokes(t.sample(circle(50, 50, 26), { count: 40 }).steps(14, (cur, next) => next.move(cur.points, (p) => mul(make(cur)(p), 0.5))), { pen });
  return [
    run((cur) => force.separation(cur, { radius: 9, excludeConnected: true }), 'pigma-005-black'),
    run((cur) => force.boundary(box, { radius: 30 }), 'stabilo-88-blue'),
    run((cur) => force.sum(force.separation(cur, { radius: 9, excludeConnected: true }), force.boundary(box, { radius: 30 })), 'stabilo-88-green'),
    strokes(t.material(circle(50, 50, 26)), { pen: 'pigma-005-black' }),
  ];
});
```

## force.nearby()

<include>/_sig/force.nearby.mdx</include>
<include>/_sig/force.adjacent.mdx</include>

Your own interaction. `nearby` finds every source within `radius` of a point, from an index built once for the state. It sums what `contribution(p, q)` returns for each source. A vertex never interacts with itself. `skip: force.adjacent(m)` leaves out the vertices joined to `p`.

```ts live
import { sketch, circle, strokes, force, sub, unit, mul, distance } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const cloud = t.scatter({ spacing: 9 });
  const spread = cloud.steps(12, (cur, next) => {
    const repel = force.nearby(cur, { radius: 14 }, (p, q) => mul(unit(sub(p, q)), 14 - distance(p, q)));
    const keep = force.boundary([[6, 6], [94, 6], [94, 94], [6, 94]], { radius: 12, strength: 3 });
    next.move(cur.points, (p) => mul(force.sum(repel, keep)(p), 0.05));
  });
  return [cloud.points.map((p) => circle(p.x, p.y, 0.6)), spread.points.map((p) => circle(p.x, p.y, 1.4, { pen: 'stabilo-88-blue' }))];
});
```
