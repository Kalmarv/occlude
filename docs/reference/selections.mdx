---
title: Selections
description: Rows of a material, chosen and combined, and what they know about each other.
---

`m.points` and `m.edges` are collections of rows. `filter` picks rows from one and returns a selection. A selection is the same kind of collection, bound to the same state, with only the rows that passed. A selection filters, iterates, maps and groups again like the whole. It copies no data. Two selections combine when they come from the same material, in this state or in an earlier one.

:::note
A row number belongs to one state. When a step adds or removes vertices, the rows get new numbers. A selection is more than its rows. Every vertex and edge carries an id, so a selection made in one state still names the same points in the next. `sel.in(state)` reads it against a later state and drops the members that are gone. A step verb takes one directly and finds the rows itself. Select again when you want to ask the new state a new question. Do not select again to keep hold of the same points.
:::

## vertex

<include>/_sig/Vertex.index.mdx</include>
<include>/_sig/Vertex.x.mdx</include>
<include>/_sig/Vertex.y.mdx</include>

One vertex, as a view of its row: `index`, `x`, `y`, and every column by name. A view reads the state it came from. To carry a view into a later state, hold its data, not the view.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 38), { count: 20 }).attribute('k', (p) => p.index % 4);
  return [strokes(ring), ring.points.map((p) => circle(p, 1 + p.k, { pen: 'stabilo-88-blue' }))];
});
```

## edge

<include>/_sig/Edge.a.mdx</include>
<include>/_sig/Edge.b.mdx</include>
<include>/_sig/Edge.length.mdx</include>
<include>/_sig/Edge.index.mdx</include>

One edge, as a view. It has its two vertex views `a` and `b` in stored order, its `length`, its row `index`, and its columns under `attrs`. Here the long edges take a pen from a column: green where the path climbs and blue where it falls. The rest of the path takes the default pen.

```ts live
import { sketch, curve, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const path = curve(t.times(9, (k) => [10 + k * 10, 50 + Math.sin(k * 1.3) * 32]), { closed: false }).edgeAttribute('climb', (e) => (e.b.y < e.a.y ? 1 : 0));
  const long = path.edges.filter((e) => e.length > 20);
  return [
    strokes(path.edges.subtract(long)),
    strokes(long.filter((e) => e.attrs.climb === 1), { pen: 'stabilo-88-green' }),
    strokes(long.filter((e) => e.attrs.climb === 0), { pen: 'stabilo-88-blue' }),
  ];
});
```

## e.center · e.adjacent

<include>/_sig/Edge.center.mdx</include>
<include>/_sig/Edge.adjacent.mdx</include>

A vertex answers `x` and `y`, and a face answers `area`, `perimeter`, `centroid` and `bounds`. An edge answers these. `center` is the middle of the wall, as a fresh pair. A segment has no area, so this is a midpoint and not a centroid. It is where a motif gets stamped, and it is how one wall says where it is.

`e.adjacent` is the edges that share a vertex with this one, this edge excluded. It is what `p.adjacent` is for a vertex, in the edge's own world. It names a neighbour once, even when the two edges share both ends. It is a selection, so it filters, draws and composes.

```ts live
import { sketch, strokes, circle, connect } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 6 }, (t) => {
  const web = connect.triangulate(t.scatter({ spacing: 15 }));
  const wall = web.edges.at(24);
  const touching = wall.adjacent;
  return [
    strokes(web.edges.subtract(touching).subtract(web.edges.rows(wall)), { pen: 'pigma-005-black' }),
    strokes(touching, { pen: 'stabilo-88-blue' }),
    strokes(web.edges.rows(wall), { pen: 'stabilo-88-green' }),
    touching.map((e) => circle(e.center, 1.2, { pen: 'stabilo-88-blue' })),
    circle(wall.center, 2.2, { pen: 'stabilo-88-green' }),
  ];
});
```

## filter()

<include>/_sig/PointSelection.filter.mdx</include>
<include>/_sig/EdgeSelection.filter.mdx</include>

The rows that pass the test, as a selection in source order. The test can return any value, and a truthy value keeps the row, as `Array.filter` does. A selection has `length`, `at(i)`, `map`, `find`, `some`, `every`, `has(view)` and `indices`. Filter a selection again to narrow it.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const cloud = t.scatter({ spacing: 7 });
  const right = cloud.points.filter((p) => p.x > 50);
  const top = right.filter((p) => p.y < 50);
  return [cloud.points.map((p) => circle(p, 0.8)), top.map((p) => circle(p, 2, { pen: 'stabilo-88-blue' }))];
});
```

## groupBy()

<include>/_sig/PointSelection.groupBy.mdx</include>
<include>/_sig/EdgeSelection.groupBy.mdx</include>

Splits a collection into one selection for each key, in the order the keys first appear. Each selection carries its `key`. The key is not a column: a later state does not know it.

```ts live
import { sketch, circle, rect, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const cloud = t.within(t.scatter({ spacing: 8 }).points, rect(4, 4, 92, 92)).extract();
  const bands = cloud.points.groupBy((p) => Math.floor(p.y / 25));
  return bands.map((sel) => sel.map((p) => circle(p, 0.6 + sel.key * 0.6, { pen: sel.key % 2 ? 'stabilo-88-blue' : undefined })));
});
```

## union() · intersect() · subtract() · complement()

<include>/_sig/PointSelection.union.mdx</include>
<include>/_sig/PointSelection.intersect.mdx</include>
<include>/_sig/PointSelection.subtract.mdx</include>
<include>/_sig/PointSelection.complement.mdx</include>

Set operations on selections of one material. `complement()` is every row that is not selected. Edge selections and face selections have the same four. The other selection can come from an earlier state, and the operation reads it by id, as `sel.in(state)` does. A selection of a material that shares no id is an error. The result keeps the key of the first selection, so `groups.reduce((a, b) => a.union(b))` gives one selection.

```ts live
import { sketch, circle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const cloud = t.scatter({ spacing: 6 });
  const left = cloud.points.filter((p) => p.x < 55);
  const low = cloud.points.filter((p) => p.y > 45);
  const both = left.intersect(low);
  return [
    left.union(low).complement().map((p) => circle(p, 0.6)),
    left.subtract(low).map((p) => circle(p, 2)),
    low.subtract(left).map((p) => circle(p, 2, { pen: 'stabilo-88-blue' })),
    both.map((p) => circle(p, 3.4, { pen: 'stabilo-88-blue' })),
  ];
});
```

## rows()

<include>/_sig/PointSelection.rows.mdx</include>
<include>/_sig/EdgeSelection.rows.mdx</include>

The selection that holds those SOURCE rows. The rows are rows of the state, never positions inside this selection, so `sel.rows([0, 3])` means the same rows whatever `sel` holds. This is the door for a relation the sketch works out for itself. Compute the rows, hand them back, and carry on with a selection. A row that is not in the state is an error. `rows` also takes the views themselves, one or a list, so `web.edges.rows(wall)` is the selection that holds the edge `wall`. A face selection has `rows` too, for the faces of its state.

Here the sketch ranks the edges by length and counts the neighbours of each point. The library has no word for either ranking. Both come back as selections.

```ts live
import { sketch, strokes, circle, connect } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 2 }, (t) => {
  const web = connect.triangulate(t.scatter({ spacing: 13 }));
  const ranked = [...web.edges].sort((a, b) => b.length - a.length);
  const longest = web.edges.rows(ranked.slice(0, 14));
  const hubs = web.points.rows([...web.points].filter((p) => p.adjacent.length >= 7));
  return [strokes(web.edges.subtract(longest), { pen: 'pigma-005-black' }), strokes(longest, { pen: 'stabilo-88-blue' }), hubs.map((p) => circle(p, 2.2))];
});
```

## extract()

<include>/_sig/PointSelection.extract.mdx</include>
<include>/_sig/EdgeSelection.extract.mdx</include>

A new material from the selection. From points: the selected points with every column and no edges. `sel.edges.extract()` is the way to keep the edges among the members. From edges: the selected edges, their endpoints, and both sets of columns. The rows keep their source order, with no gaps. The new material starts its own history. This is the one way to get independent material out of a selection. From faces: the edges and corners of the selected faces, with every column and every id. A builder such as `connect.chain(sel)` also keeps the ids of the members, so `sel.in(result)` finds them.

```ts live
import { sketch, circle, strokes, group } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 60, 34), { count: 40 });
  const arc = ring.edges.filter((e) => e.a.y < 60 && e.b.y < 60).extract();
  const start = arc.points.at(0);
  return [strokes(ring, { pen: 'pigma-005-black' }), group({ translate: [0, -22] }, strokes(arc, { pen: 'stabilo-88-blue' }), circle(start, 2, { pen: 'stabilo-88-blue' }))];
});
```

## points.edges · edges.points · edges.curves()

<include>/_sig/PointSelection.edges.mdx</include>
<include>/_sig/EdgeSelection.edges.mdx</include>
<include>/_sig/EdgeSelection.points.mdx</include>
<include>/_sig/EdgeSelection.curves.mdx</include>

`points.edges` is the source edges with both ends in the point selection. `edges.edges` is the selection itself. Every geometry value then answers the word, and a consumer reads any of them the same way. `edges.points` is the endpoints of an edge selection, each once. `edges.curves()` walks the selected edges into chains, each edge once, with ends and junctions those of the selection alone. `strokes(edges)` draws those chains.

```ts live
import { sketch, circle, strokes, connect } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const web = connect.triangulate(t.scatter({ spacing: 12 }));
  // The edges with both ends inside the ring of points, walked into chains.
  const inner = web.points.near([50, 50], { radius: 30 }).edges;
  const chains = inner.curves();
  return [
    strokes(web.edges.subtract(inner), { pen: 'pigma-005-black' }),
    strokes(chains.filter((c, i) => i % 2 === 0), { pen: 'stabilo-88-green' }),
    strokes(chains.filter((c, i) => i % 2 === 1), { pen: 'stabilo-88-blue' }),
  ];
});
```

## p.adjacent · p.edges · points.near() · edges.near()

<include>/_sig/Vertex.adjacent.mdx</include>
<include>/_sig/Vertex.edges.mdx</include>
<include>/_sig/PointSelection.near.mdx</include>
<include>/_sig/EdgeSelection.near.mdx</include>

Two different questions. `p.adjacent` is topology: the points an edge joins this one to. `points.near(p, { radius })` is distance: the points closer than `radius`, joined or not. A rule wants one or the other. Name the right one and the rule stays honest. `a.adjacent.has(b)` tells you that two points share an edge.

`p.edges` is the same neighbourhood as edges. `p.edges.length` is the degree: a vertex with one edge is an end, and a vertex with three or more is a junction.

`edges.near(p, { radius })` is the same distance question for walls, and it measures the whole segment. The radius is a length in the space of the material. A long wall passing close to a place is near it, whichever end you measure from. The topological question for a wall is `e.adjacent`.

```ts live
import { sketch, circle, rect, strokes, connect } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 5 }, (t) => {
  const tree = connect.tree(t.within(t.scatter({ spacing: 12 }).points, rect(6, 6, 88, 88)).extract());
  const hub = [...tree.points].reduce((a, b) => (b.edges.length > a.edges.length ? b : a));
  // Joined to the hub, and passing close to it: two different questions,
  // and the same wall may answer both. Each wall is drawn once.
  const spokes = hub.edges;
  const close = tree.edges.near(hub, { radius: 13 }).subtract(spokes);
  return [
    strokes(tree.edges.subtract(spokes).subtract(close), { pen: 'pigma-005-black' }),
    strokes(spokes, { pen: 'stabilo-88-blue' }),
    strokes(close, { pen: 'stabilo-88-green' }),
    // Close to the hub, joined or not: a ring of points.
    tree.points.near(hub, { radius: 26 }).map((q) => circle(q, 2)),
    circle(hub, 3, { pen: 'stabilo-88-blue' }),
  ];
});
```

:::note
`near` builds one index for each radius and keeps it on the state. A whole pass of queries at one radius pays for one grid. A selection of part of a state answers with its own members only.
:::

## edges.crossing()

<include>/_sig/EdgeSelection.crossing.mdx</include>

The edges that a straight move from `a` to `b` goes through. The segment must pass from one side of the edge to the other. The edge must do the same across the segment. This is the question a growth rule asks before it puts down a new wall.

Both sides are strict, and the test is exact. Contact at an end is not a crossing. A move that stops on an edge has not gone through it. Nor has a move that starts at one or touches an edge's endpoint. A move that lies along an edge changes no side, so it is not a crossing either. `query.edges(...).firstHit(from, to)` answers a different question: it names the first edge on the way and the place it meets.

The candidates come from the same grid that `near` keeps on the state. A rule can ask this for every tip at every step. A selection of part of a state answers with its own members only.

Below, every tip follows a noise field. A tip takes its next step only into clear paper, so the lines run beside each other and stop where they meet. The blue rings are the seeds.

```ts live
import { sketch, strokes, circle, add, mul, fromAngle } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 7 }, (t) => {
  const b = t.bounds();
  const seeds = t.scatter({ spacing: 8 });
  const tangle = seeds.steps(160, (cur, next) => {
    for (const p of cur.points) {
      if (p.edges.length > 1) continue;
      const to = add(p, mul(fromAngle(t.noise(p.x * 0.02, p.y * 0.02) * Math.PI * 2), 1.8));
      if (to[0] < 2 || to[1] < 2 || to[0] > b.w - 2 || to[1] > b.h - 2) continue;
      if (cur.edges.crossing(p, to).indices.length > 0) continue;
      next.extrude(p, () => ({ position: to }), { inherit: true });
    }
  });
  return [strokes(tangle), seeds.points.map((p) => circle(p, 0.5, { pen: 'stabilo-88-blue' }))];
});
```

## adjacent() · connected() · components()

<include>/_sig/PointSelection.adjacent.mdx</include>
<include>/_sig/PointSelection.connected.mdx</include>
<include>/_sig/PointSelection.components.mdx</include>

The same three words a whole selection says, on points, on edges and on faces. `adjacent()` is one step out: every point an edge joins to a member, members excluded. `connected()` is all the way out: the members plus everything reachable from them. `components()` partitions the MEMBERS into pieces, joined by the edges among them alone, and keys them `0, 1, 2 …` as `groupBy` does. A loose vertex is a piece of its own.

```ts live
import { sketch, strokes, connect } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const lattice = connect.unimpeded(t.scatter({ spacing: 9 }), { room: 3.5 });
  return lattice.points.components().map((piece) => strokes(piece.edges, { pen: piece.key % 2 ? 'stabilo-88-blue' : 'pigma-005-black' }));
});
```

`connected()` reaches the whole piece that a point sits in. The far end can be a long way off. Here it starts at the left edge and spreads through everything the lattice joins to it.

```ts live
import { sketch, strokes, circle, connect } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 4 }, (t) => {
  const lattice = connect.unimpeded(t.scatter({ spacing: 9 }), { room: 3.5 });
  const seed = lattice.points.filter((p) => p.x < 0.1 * t.bounds().w);
  const piece = seed.connected();
  return [
    strokes(lattice.points.subtract(piece).edges, { pen: 'pigma-005-black' }),
    strokes(piece.edges, { pen: 'stabilo-88-blue' }),
    seed.map((p) => circle(p, 1.6)),
  ];
});
```

## query.edges()

<include>/_sig/query.edges.mdx</include>

A spatial index over the edges of one state, built once. `nearest(position, { within })` gives the closest edge within a distance. `firstHit(from, to)` gives the first edge that a straight move would cross. Both return a hit or `null`. A hit from `nearest` has `edge`, `position` (the closest point, as a pair), `distance`, and `t`, the fraction along the edge. A hit from `firstHit` has the same fields, with `position` the crossing point and `distance` the length travelled from `from`. `excludeIncident: p` ignores the edges that touch the vertex `p`. Both read the state that made the query, and neither edits it. Build the query outside the callback that uses it.

```ts live
import { sketch, circle, strokes, query, line, connect } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const web = connect.triangulate(t.scatter({ spacing: 14 }));
  const q = query.edges(web);
  const probes = t.scatter({ spacing: 15 });
  return [strokes(web, { pen: 'pigma-005-black' }), probes.points.map((p) => {
    const hit = q.nearest(p, { within: 10 });
    return [circle(p, 1.2, { pen: 'stabilo-88-blue' }), hit && [line(p, hit.position, { pen: 'stabilo-88-blue' }), circle(hit.position, 0.6)]];
  })];
});
```

## pairs()

<include>/_sig/PointSelection.pairs.mdx</include>
<include>/_sig/EdgeSelection.pairs.mdx</include>

Every pair of members the predicate accepts, as views: `[a, b]` two at a time. A member is never paired with itself. `radius` takes the candidates from the spatial index. Write that form. Edges are near each other by their MIDDLES. Without a radius this is the full product. The library permits it, and it costs what it sounds like.

When the two selections hold the same rows, each pair appears once, in no order. The predicate sees `(a, b)` with `a` before `b` by row. It never sees `(b, a)`. Two different selections give the ordered product instead.

`t.pick(pairs)` takes one pair at a time, because `t.pick` takes anything with `length` and `at`.

```ts live
import { sketch, circle, line } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 3 }, (t) => {
  const cloud = t.relax(t.scatter({ spacing: 11 }), { iterations: 2 });
  // The relation this drawing is about: two points close enough to see each
  // other, and level enough to be a rung. The sketch states it; `pairs`
  // finds it.
  const rungs = cloud.points.pairs(cloud.points, (a, b) => Math.abs(a.y - b.y) < 5, { radius: 20 });
  return [
    cloud.points.map((p) => circle(p, 1.1)),
    rungs.map(([a, b]) => line(a, b, { pen: 'stabilo-88-blue' })),
  ];
});
```

:::note
**A pair in a step.** A pair is two rows. A batch is a set of edits to rows. Two pairs can then ask contradicting things of one row. The batch rules decide. They are the same rules as for any other edit:

| Two pairs ask | What happens |
|---|---|
| to move the same row | the moves add up, as two `next.move` calls do |
| to set the same column of one row | the last write wins |
| to connect the same two rows | one edge; a second `connect` of a pair that exists is ignored |
| to split one edge at different parameters | both splits happen, in edge then parameter order |
| to remove a row that another pair moves or connects | the batch throws and publishes nothing |
:::

## where

Several material methods take `where`: the part of the material the operation may touch.

```ts
m.warp({ from, to, where: m.points.filter((p) => p.y > 30) })
```

It names the ELIGIBLE region. The operation's own rule still applies inside it. A method takes the domain it uses: give a method that moves points an edge selection, and it takes the endpoints. A face selection or one face gives its corners to a method that moves points, and its edges to a method on edges. A point selection, read as edges, gives the edges among its members, as `strokes(sel)` draws them. For the edges touching the members, say `sel.edges.adjacent()`. With no `where` the whole material is eligible. A method refuses a selection of another material, by name.

`m.warp` and `m.snap` move points and leave the rest where they are. `m.resample` works on edges. Consecutive eligible edges make a run, and a run keeps its two end vertices, so the chain stays one chain. A row outside the region keeps its id.

```ts live
import { sketch, strokes, circle } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 4 }, (t) => {
  const ring = t.sample(circle(50, 50, 36), { count: 90 });
  // Only the right-hand half is snapped onto the field's ridges. The left
  // half keeps the circle it was, and the two are still one chain.
  const right = ring.points.filter((p) => p.x > 50);
  const rough = ring.snap((x, y) => Math.sin(x / 4) + Math.sin(y / 4), { radius: 6, where: right });
  return [strokes(ring, { pen: 'stabilo-88-blue' }), strokes(rough)];
});
```
