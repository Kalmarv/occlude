---
title: Selections
description: Rows of a material, chosen and combined, and what they know about each other.
---

`m.points` and `m.edges` are collections of rows. `filter` picks rows from one and returns a selection. A selection is the same kind of collection, bound to the same state, with only the rows that passed. A selection filters, iterates, maps and groups again like the whole. It copies no data. Two selections combine only when they come from the same state.

:::note
A row number belongs to one state. When a step adds or removes vertices, the rows get new numbers. A selection from the step before is not valid in the step after. Select again from the current state.
:::

## vertex

<include>/_sig/Vertex.index.mdx</include>
<include>/_sig/Vertex.x.mdx</include>
<include>/_sig/Vertex.y.mdx</include>

One vertex, as a view of its row: `index`, `x`, `y`, and every column by name. A view reads the state it came from. To carry a view into a later state, hold its data, not the view.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 50, 38), { count: 20 }).attribute('k', (p) => p.index % 4);
  return [strokes(ring), ring.points.map((p) => circle(p.x, p.y, 1 + p.k, { pen: 'stabilo-88-blue' }))];
});
```

```ts live
import { sketch, curve, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const path = curve(t.times(9, (k) => [10 + k * 10, 50 + Math.sin(k * 1.3) * 32]), { closed: false });
  const long = path.edges.filter((e) => e.length > 20);
  return [strokes(path), strokes(long, { pen: 'pigma-05-black' })];
});
```

## filter()

<include>/_sig/PointSelection.filter.mdx</include>
<include>/_sig/EdgeSelection.filter.mdx</include>

The rows that pass the test, as a selection in source order. A selection has `length`, `at(i)`, `map`, `find`, `some`, `every`, `has(view)` and `indices`. Filter a selection again to narrow it.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const cloud = t.scatter({ spacing: 7 });
  const right = cloud.points.filter((p) => p.x > 50);
  const top = right.filter((p) => p.y < 50);
  return [cloud.points.map((p) => circle(p.x, p.y, 0.8)), top.map((p) => circle(p.x, p.y, 2, { pen: 'stabilo-88-blue' }))];
});
```

## groupBy()

<include>/_sig/PointSelection.groupBy.mdx</include>
<include>/_sig/EdgeSelection.groupBy.mdx</include>

Splits a collection into one selection for each key, in the order the keys first appear. Each selection carries its `key`. The key is not a column: a later state does not know it.

```ts live
import { sketch, circle, strokes } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const cloud = t.scatter({ spacing: 8 }).points.filter((p) => p.x > 4 && p.x < 96 && p.y > 4 && p.y < 96).extract();
  const bands = cloud.points.groupBy((p) => Math.floor(p.y / 25));
  return bands.map((sel) => sel.map((p) => circle(p.x, p.y, 0.6 + sel.key * 0.6, { pen: sel.key % 2 ? 'stabilo-88-blue' : undefined })));
});
```

## union() · intersect() · subtract() · complement()

<include>/_sig/PointSelection.union.mdx</include>
<include>/_sig/PointSelection.intersect.mdx</include>
<include>/_sig/PointSelection.subtract.mdx</include>
<include>/_sig/PointSelection.complement.mdx</include>

Set operations on selections of the same state. `complement()` is every row that is not selected. Edge selections have the same four.

```ts live
import { sketch, circle } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const cloud = t.scatter({ spacing: 6 });
  const left = cloud.points.filter((p) => p.x < 55);
  const low = cloud.points.filter((p) => p.y > 45);
  const both = left.intersect(low);
  return [cloud.points.map((p) => circle(p.x, p.y, 0.7)), left.subtract(low).map((p) => circle(p.x, p.y, 1.8)), both.map((p) => circle(p.x, p.y, 1.8, { pen: 'stabilo-88-blue' }))];
});
```

## extract()

<include>/_sig/PointSelection.extract.mdx</include>
<include>/_sig/EdgeSelection.extract.mdx</include>

A new material from the selection. From points: the selected points with every column and no edges. From edges: the selected edges, their endpoints, and both sets of columns. The rows keep their source order, with no gaps. The new material starts its own history. This is the one way to get independent material out of a selection.

```ts live
import { sketch, circle, strokes, group } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const ring = t.sample(circle(50, 60, 34), { count: 40 });
  const arc = ring.edges.filter((e) => e.a.y < 60 && e.b.y < 60).extract();
  return [strokes(ring, { pen: 'pigma-005-black' }), group({ translate: [0, -22] }, strokes(arc, { pen: 'stabilo-88-blue' }), arc.points.filter((p) => p.index === 0).map((p) => circle(p.x, p.y, 2, { pen: 'stabilo-88-blue' })))];
});
```

## points.edges · edges.points · edges.curves()

<include>/_sig/PointSelection.edges.mdx</include>
<include>/_sig/EdgeSelection.points.mdx</include>
<include>/_sig/EdgeSelection.curves.mdx</include>

`points.edges` is the source edges with both ends in the point selection. `edges.points` is the endpoints of an edge selection, each once. `edges.curves()` walks the selected edges into chains, each edge once, with ends and junctions those of the selection alone. `strokes(edges)` draws those chains.

```ts live
import { sketch, circle, strokes, connect } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const web = connect.triangulate(t.scatter({ spacing: 12 }));
  const inner = web.points.filter((p) => Math.hypot(p.x - 50, p.y - 50) < 30);
  return [strokes(web, { pen: 'pigma-005-black' }), strokes(inner.edges, { pen: 'pigma-05-black' })];
});
```

## p.adjacent · p.edges · points.near()

<include>/_sig/Vertex.adjacent.mdx</include>
<include>/_sig/Vertex.edges.mdx</include>
<include>/_sig/PointSelection.near.mdx</include>

Two different questions. `p.adjacent` is topology: the points an edge joins this one to. `points.near(p, { radius })` is distance: the points closer than `radius`, joined or not. A rule wants one or the other. Name the right one and the rule stays honest. `a.adjacent.has(b)` tells you that two points share an edge.

`p.edges` is the same neighbourhood as edges. `p.edges.length` is the degree: a vertex with one edge is an end, and a vertex with three or more is a junction.

```ts live
import { sketch, circle, strokes, line, connect } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 5 }, (t) => {
  const tree = connect.tree(t.scatter({ spacing: 12 }).points.filter((p) => p.x > 6 && p.x < 94 && p.y > 6 && p.y < 94).extract());
  const hub = [...tree.points].reduce((a, b) => (b.adjacent.length > a.adjacent.length ? b : a));
  return [
    strokes(tree),
    // Joined to the hub: blue.
    [...hub.adjacent].map((q) => line(hub.x, hub.y, q.x, q.y, { pen: 'stabilo-88-blue' })),
    // Close to the hub, joined or not: a ring.
    [...tree.points.near(hub, { radius: 26 })].map((q) => circle(q.x, q.y, 2, { pen: 'stabilo-88-green' })),
    circle(hub.x, hub.y, 3),
  ];
});
```

:::note
`near` builds one index for each radius and keeps it on the state. A whole pass of queries at one radius pays for one grid. A selection of part of a state answers with its own members only.
:::

## adjacent() · connected() · components()

<include>/_sig/PointSelection.adjacent.mdx</include>
<include>/_sig/PointSelection.connected.mdx</include>
<include>/_sig/PointSelection.components.mdx</include>

The same three words a whole selection says, on points and on edges. `adjacent()` is one step out: every point an edge joins to a member, members excluded. `connected()` is all the way out: the members plus everything reachable from them. `components()` partitions the MEMBERS into pieces, joined by the edges among them alone, and keys them `0, 1, 2 …` as `groupBy` does. A loose vertex is a piece of its own.

```ts live
import { sketch, strokes, connect } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const lattice = connect.unimpeded(t.scatter({ spacing: 9 }), { room: 3.5 });
  return lattice.points.components().map((piece) => strokes(piece.edges, { pen: piece.key % 2 ? 'stabilo-88-blue' : 'pigma-005-black' }));
});
```

## query.edges()

<include>/_sig/query.edges.mdx</include>

A spatial index over the edges of one state, built once. `nearest(position, { within })` gives the closest edge within a distance. `firstHit(from, to)` gives the first edge that a straight move would cross. Both return a hit or `null`. A hit from `nearest` has `edge`, `position` (the closest point, as a pair), `distance`, and `t`, the fraction along the edge. A hit from `firstHit` has the same fields, with `position` the crossing point and `distance` the length travelled from `from`. `excludeIncident: p` ignores the edges that touch the vertex `p`. Both read the state that made the query, and neither edits it. Build the query outside the callback that uses it.

```ts live
import { sketch, circle, strokes, query, line, connect } from 'occlude';

export default sketch({ aspect: [1, 1] }, (t) => {
  const web = connect.triangulate(t.scatter({ spacing: 14 }));
  const q = query.edges(web);
  const probes = t.scatter({ spacing: 15 });
  return [strokes(web, { pen: 'pigma-005-black' }), probes.points.map((p) => { const hit = q.nearest(p, { within: 10 }); return hit ? line(p.x, p.y, hit.position[0], hit.position[1], { pen: 'stabilo-88-blue' }) : circle(p.x, p.y, 1); })];
});
```

## rows()

<include>/_sig/PointSelection.rows.mdx</include>
<include>/_sig/EdgeSelection.rows.mdx</include>

The selection that holds those SOURCE rows. The rows are rows of the state, never positions inside this selection, so `sel.rows([0, 3])` means the same rows whatever `sel` holds. This is the door for a relation the sketch works out for itself. Compute the rows, hand them back, and carry on with a selection. A row that is not in the state is an error.

## pairs()

<include>/_sig/PointSelection.pairs.mdx</include>
<include>/_sig/EdgeSelection.pairs.mdx</include>

Every pair of members the predicate accepts, as views: `[a, b]` two at a time. A member is never paired with itself. `radius` takes the candidates from the spatial index. Write that form. Edges are near each other by their MIDDLES. Without a radius this is the full product. The library permits it, and it costs what it sounds like.

When the two selections hold the same rows, each pair appears once, in no order. The predicate sees `(a, b)` with `a` before `b` by row. It never sees `(b, a)`. Two different selections give the ordered product instead.

`t.pick(pairs)` takes one pair at a time, because `t.pick` takes anything with `length` and `at`.

```ts live
import { sketch, circle, line } from 'occlude';

export default sketch({ aspect: [1, 1], seed: 3 }, (t) => {
  const cloud = t.relax(t.scatter({ spacing: 11 }), { iterations: 2 });
  // The relation this drawing is about: two points close enough to see each
  // other, and level enough to be a rung. The sketch states it; `pairs`
  // finds it.
  const rungs = cloud.points.pairs(cloud.points, (a, b) => Math.abs(a.y - b.y) < 5, { radius: 20 });
  return [
    cloud.points.map((p) => circle(p.x, p.y, 1.1)),
    rungs.map(([a, b]) => line(a.x, a.y, b.x, b.y, { pen: 'stabilo-88-blue' })),
  ];
});
```

:::note
**A pair in a step.** A pair is two rows. A batch is a set of edits to rows. Two pairs can then ask contradicting things of one row. The batch rules decide. They are the same rules as for any other edit:

| Two pairs ask | What happens |
|---|---|
| to move the same row | the moves add up, as two `next.move` calls do |
| to set the same column of one row | the last write wins |
| to connect the same two rows | one edge; a second `connect` of a pair that exists is ignored |
| to split one edge at different parameters | both splits happen, in edge then parameter order |
| to remove a row that another pair moves or connects | the batch throws and publishes nothing |
:::
