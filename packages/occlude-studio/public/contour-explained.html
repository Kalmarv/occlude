Geometry for a moving pen

Let the pen
follow the shape.

A filled shape is easy to imagine. Drawing it with one moving pen means deciding where the ink goes, where the gaps remain, and when lifting the pen is worth it. This is how Occlude’s contour fill makes those decisions.

01 / The physical problem

A lift takes time, too.

A hatch fill draws a row, lifts the pen, moves to the next row, and lowers it again. On a dense drawing, those little pauses add up.

Contour fill follows the outline inward, drawing a family of nested loops. Short connections can turn many loops into a long pen-down run. Holes and branches can still deserve a lift.

One measured disc

415 fill runs → 2

Estimated plot time fell from 20.96 to 18.52 minutes against default solid fill.

The improvement in time is smaller than the reduction in lifts: the pen still has to draw the ink. These are estimator results on one fixture, not timed physical plots.

The aim is a quicker drawing, with complete coverage. A single unbroken path is optional.

02 / From an area to paths

Draw everywhere the border is equally far away.

Imagine walking inside a shape while staying exactly one millimetre from its nearest boundary. Your route is an offset contour. Repeat at two millimetres, three millimetres, and so on.

For a pen with width w, the first regular path sits approximately half a pen width inside the boundary. The next paths are one requested spacing s apart.

distance = w / 2 + k × s   for k = 0, 1, 2, …
01. Resolve the area

What is actually visible?

Apply the shape’s deformation and clips, then subtract opaque shapes in front. A newly exposed hole is a boundary to follow.

02. Build the distance geometry

Which edge is nearest?

A Voronoi diagram divides the interior by its nearest boundary segment or vertex. Within each part, distance contours have simple formulas.

03. Extract each level

Lines and circular arcs

Each requested distance is constructed from that diagram. We do not offset a slightly approximate result again and again.

This is related to a signed distance field, or SDF: a field that describes distance to a boundary, together with which side you are on. Occlude represents this distance geometry with points and segments rather than sampling a dense grid of pixels.

Original curves still need care. Cubics are converted with a bounded approximation; generated ink is checked against the original visible geometry. If curved input fails that check, the engine can rebuild from the original curves at a tighter tolerance.

03 / Where the fronts meet

The last loop can leave an empty middle.

“Offset the border and repeat” gets most of the way there. But a narrow central strip can remain after the last complete loop fits. The same thing happens in thin fingers, between holes, and where a shape splits into branches.

The Voronoi diagram also describes where different boundary fronts meet: its interior medial branches. Those branches help locate the remaining work. Occlude uses vector coverage tests to choose short cleanup strokes or taps, and allows them to overlap existing ink.

Complete loops, short transitions

A run enters a loop, draws a full lap, returns to the same point, and can take a short connector to another loop. It does not remove a slice of the loop and leave a seam.

Once a loop has an entry point, that point is also its exit. The next connection has to work from there; otherwise, accepting a lift is fine.

For a separated texture, use fill('contour', { connectors: false }). This skips optional transitions between loops and cleanup marks; necessary cleanup ink remains. The default is true.

Visible endpoints are not enough

A connector between two visible points could still cross a hole. Its whole length has to remain in the permitted area.

The engine checks generated paths before finishing modifiers. Decimation or dash can then create intentional breaks, and displacement keeps its usual behavior.

Why can checking visibility be fast?

If a rectangle contains an entire proposed primitive and a point already certified visible, and that rectangle crosses no source, clip, or occluder boundary, visibility cannot change inside it. Occlude can reuse the certificate. Otherwise, it performs the full clipping check. This saves repeated work without relying only on endpoints or a sampled midpoint.

What does “covered” mean at a sharp corner?

A round pen cannot fill every mathematical corner while keeping its whole footprint inside that corner. The coverage contract distinguishes the nib-reachable interior from thin features, where existing centerline clipping and nib judging apply. Tests include actual thin appendages; checking only an eroded shape would miss the very feature at risk.

04 / Making artwork

Change the material. Change the texture.

thicken controls the area that exists. Its radius can vary across the drawing. fill('contour') draws inside that area. Its spacing controls the distance between ink paths. Decimation breaks those paths into separate marks.

These operations compose, so there is no need for a separate “radial contour” mode or “recursive contour” mode.

const area = thicken(material, {
  radius: (p) => t.map(
    Math.hypot(p.x - 50, p.y - 50),
    0, 50, 0.2, 2.2,
  ),
});

return [
  decimate(0.45, polygon(area, {
    stroke: false,
    fill: fill('contour'),
  })),
  polygon(area), // Keep a separate, intact outline.
];

Excerpt: material is the source linework and t is the sketch toolkit. Full runnable versions are in the live examples.

Three independent choices

Radius → the silhouette

Constant, horizontal or radial thickening changes the area being filled.

Spacing → the texture

Default spacing is 0.9 times the fill pen width. Wider-than-nib spacing deliberately leaves gaps; dense cleanup is disabled.

Decimation → broken marks

Intentional fragmentation can add many lifts. A separate outline preserves a readable edge.

Recorded on a Linux system reporting an AMD Ryzen 5 3600. Studio’s WASM runs on the browser’s machine, so another laptop can be faster or slower. Rendering time and physical plot ETA measure different things.

Independent coverage diagnostics checked about 142,000 points of the original fine-width region and found no misses. At a 0.01 mm nib width, the largest measured distance to a path was 0.004749 mm—inside the 0.005 mm nib radius. Sampling is evidence, not a proof for every possible shape.

The limits are part of the result.

The finest-width stress case generated about 2.9 million fill primitives. A recorded fine-width run reached about 2.87 GB of WASM linear-memory capacity after rendering and planning. That excludes JavaScript and page memory.

Pathological geometry can still exceed work or memory budgets, and Studio retains its 20-second worker timeout. The existing 0.005 mm input grid can collapse smaller authored details before filling begins. No universal correctness, speed or minimum-lift claim is made.

What went wrong with the conversion-budget error?

A preflight estimate divided total curve length by the conversion tolerance. But a long, nearly straight curve may flatten into very few segments, and circular arcs can remain analytic. The estimate rejected a tractable sketch before doing the conversion. Removing it let the reported 12-inch sketch, seed 1493547082, complete in 3.63 seconds in Studio. The follow-up also merges exactly collinear degree-two boundary segments before Voronoi construction, fixing a missing-junction case without changing the quantized boundary.

How is approximation kept under control?

The aggregate construction tolerance is the minimum of 0.01 mm, pen width / 20 and spacing / 10. Parts of that allowance are reserved for curve conversion, quantization, level adjustment and cleanup. Each level is constructed independently. Integer topology is validated after rounding, and generated geometry is checked against the original scene before modifiers.

06 / Established ideas, a specific implementation

A useful adaptation of machining geometry.

Voronoi-based pocket paths and residual cleanup have a long history in CNC machining. Occlude adapts those ideas to a round pen, visible ink, short local connections and a single-threaded browser runtime.

The implementation uses boostvoronoi 0.12.1 for the point/segment diagram. Occlude supplies the surrounding normalization, contour extraction, coverage decisions, routing, visibility validation and integration.

The local coverage tests and visibility-certificate reuse are worth explaining and comparing with prior work. Their mathematical novelty has not been established. This document is an engineering explanation, not a claim of a new theorem.
