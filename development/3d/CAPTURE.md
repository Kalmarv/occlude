# Frozen 3D result provenance

Save result now asks the worker for the 3D inputs belonging to the named current plan. The worker captures the committed camera/paper frame, realized meshes and source attributes, object transforms and section support, authored wires, generated hatch/section attachments, compiled source, resolved seed, engine stamp, precision policy, modeling counters and available adapter details. It stores plain structured data, not callbacks, generator closures or GPU resources. Capture is lazy and owned by the committed result; subsequent construction preview cameras cannot replace it. A stale plan hash is rejected.

The existing result store persists this optional versioned 3D record alongside its selected plan and SVG. Reopening adopts the saved plan and retained provenance without executing the source or rerunning procedural GPU work. Ordinary 2D results have no added 3D record. Optimization adoption retains the originating capture, while loading a different saved plan replaces it and releases the old inspection/construction execution references.

Save captures the execution timing profile in force, including the original profile of a reopened frozen result, rather than substituting a newly active library profile. Save also captures the actual displayed paper color once, including a UI-supplied color when the sketch did not declare one. Metadata and SVG use that same captured color across awaits. This closes a save/reopen gap where the SVG kept the UI color but the saved paper record omitted it.

Two focused tests cover JSON round trips of committed frames, geometry, attributes and generated attachments without callbacks, independent captured ownership, and absent 3D metadata for a 2D execution. The Studio suite passes 144 tests in 19 files and its typecheck passes. Changed-library responses are browser test fixtures; no shared library definitions are overwritten. Only the verifier's newly created result is deleted afterward.
