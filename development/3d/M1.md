# M1 GPU walking skeleton evidence

This is the first working renderer slice, not completion of the 3D MVP.

## Reproduce

Start only the isolated dev service using the commands in STATUS.md. Open
`/three.html` at port 5273. Cloudflare can use `dev-occlude.ivyhq.xyz` and an
HTTP origin on port 5273. The nested name `dev.occlude.ivyhq.xyz` needs separate
edge certificate coverage; the observed TLS failure happens before Vite.
The configured dev hostnames are explicitly allowed through OCCLUDE_DEV_HOSTS.

Hardware-browser verification from packages/occlude-studio:

```sh
xvfb-run -a node tools/verify-three.mjs
```

The script selects the NVIDIA Vulkan ICD, runs a headed Chrome on the virtual
display and requires a non-fallback adapter. Override OCCLUDE_CHROME,
VK_DRIVER_FILES, OCCLUDE_GPU_URL or OCCLUDE_GPU_EVIDENCE for another machine.
`--software` is a separate correctness lane and never hardware evidence.
The launch flags and browser version are captured in playwright-m1/report.json.

## Verified behavior

- Ten CPU tests include independent Möller–Trumbore ray comparisons (3,680
  interval-interior checks), analytic hidden intervals, perspective depth,
  near/far clipping through the eye, winding, own-plane behavior and gap union.
- Actual hardware GPU computes the partly hidden interval in one dispatch with
  zero CPU refinements. Two SVG styles reuse it. This is geometric visibility,
  not sampled depth-buffer visibility.
- A depth-tested WebGPU triangle/wire viewport uses portable triangle stroke quads.
- Playwright compares 128 mixed orthographic/perspective pairs to f64, forces
  eight bounded batches, checks empty work, cancellation, snapshot ownership,
  coplanar refinement and device loss. It downloads actual Occlude SVG output.
- Camera/depth data and interval modules can be imported in a CPU process with
  no GPU initialization. GPU sessions explicitly own device and buffer leases.
- Source code is independently implemented. WGSL rounding and mapAsync lifecycle
  were checked against the W3C WGSL specification and MDN API documentation.

## Measurements

Host: NVIDIA GeForce RTX 2060, driver 595.71.05; browser reports NVIDIA/Turing,
non-fallback. These tiny correctness cases do not establish a performance win.
GPU timings include upload/readback/refinement; cold device time includes adapter
request and pipeline creation. Total lab time also includes WASM and SVG finishing.

| Case | GPU wall ms | CPU reference ms | Dispatches | Refinements |
| --- | ---: | ---: | ---: | ---: |
| orthographic one pair | 43.40 | 0.10 | 1 | 0 |
| perspective one pair | 8.80 | 0.00 | 1 | 0 |
| 128 mixed pairs, 17-pair capacity | 53.30 | 0.40 | 8 | 0 |

Cold device/pipeline: 1693.00 ms; total cold lab: 1793.30 ms.

The one-pair session reserves 8 MiB; the deliberately constrained batch session
reserves 2,176 bytes and transfers 14,336 bytes for 128 pairs. Raster canvas is
720×480; final visibility does not depend on its resolution. The ordinary
orthographic endpoint differs from the analytic parameter by about 3e-8.
This is fixture evidence, not yet a universal physical error guarantee.

## Remaining work

Revision-aware worker integration, shared classified graph and public async sketch
integration are still pending. The current lab is a main-thread host of the same
explicit GPU session and consumes a deliberately tiny authored triangle/wire.
It does not yet have a mesh broad phase, feature extraction, generic line-set
chaining, procedural mesh edits, hatching, section contours, persistent camera
controls or the three full demonstrations. M2–M5 and those M1 integration details
remain required. No large-scene acceleration, production readiness, precision
certification or Blender comparison is claimed.

GPU uncertainty uses a conservative f32 packing/dot/division envelope and f64
fallback, but adversarial scale and topology precision remain part of hardening.
The input pair API is bounded per dispatch, not yet a complete scene renderer;
large-scene conservative candidate generation is the next renderer step.

See playwright-m1/report.json, orthographic.png, perspective.png and visibility.svg.
Playwright video remains in the task-local evidence directory.

Final verification runs against the production bundle served by the isolated dev
service, including packaged shaders and WASM. pnpm check passed Rust, TS, both
typechecks, docs, unchanged ink oracle, build, WASM MD5 and smoke gates.

The optional Chrome/SwiftShader lane passes its first fixture but currently loses
the device before the perspective rerun (reported as `Device was destroyed`).
No application `destroy()` call was observed in an instrumented reproduction.
This lane is not marked passed; browser/backend recovery remains an explicit
hardening item. The hardware NVIDIA lane passes both projections and all batch
lifecycle checks in the production bundle.

Production checkout remains clean and the original production/development
container IDs and start times are unchanged. Only occlude-3d-dev-1 was recreated.
