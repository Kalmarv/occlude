# Portable camera configuration

`SketchOptions.cameras3` captures camera values by scene key. `lineArt3({ id: 'main', ... })` uses `cameras3.main`; unnamed scenes receive `@1`, `@2`, etc. in classification-request order. Explicit IDs are unique and cannot begin with `@`. Give scenes IDs when their order can change. Only own configuration entries count, including prototype-like names. The pure scene retains its declared camera; the classified frame records the effective configured camera.

Execution captures and validates configuration cameras before modeling. Visibility reads that captured configuration. Camera commits preserve keys for unchanged and replaced scenes, update the relevant configuration entry and continue to reuse unrelated classifications. Studio construction metadata reports the effective camera rather than the scene default. This works headlessly as well as through the GPU worker.

Commit view now writes the resolved camera configuration into the editor and local draft without running the model again. The existing Save/Download paths carry that source. The source edit uses the existing Prettier TypeScript parser, loaded on demand, and does not evaluate sketch code on the main thread. It follows normal named/namespace imports and exported definitions, preserves configuration expressions and comments, and replaces its trailing camera property on subsequent commits. A default-exported factory is captured once with a configuration overlay that preserves deferred getter access and inherited definition properties. Ambiguous named exports require an explicit default export before committing; the request has not run when source preparation fails.

Core tests cover configured projection against fresh-camera vectors, scene-default immutability, headless replay, stable numbered keys across commits, duplicate IDs and prototype-like names. Sixteen source-edit tests cover aliases, named/default exports, config expressions, spreads/getters, default factories, repeated edits, inherited properties and single/deferred evaluation.

The first download/reopen comparison found matching cameras but different plans: the docs supplied a 200 mm square, while reopening an undeclared sheet used the host's A4 default. The composition example now explicitly declares its square sheet and 5% margin; its prior ink remains unchanged. This preserves the intentional host-paper behavior of sketches that omit paper instead of hiding a changed input in a camera test.

Source Playwright on nonfallback NVIDIA Turing passes camera commit with no repeated model invocation, cancellation/stale-request checks, actual sketch download, reopening the downloaded source with the exact same camera and plan hash, and the saved-result changed-library round trip. Evidence is retained locally under `playwright-camera-config-source/`. Reopening a sketch intentionally runs its model once; reopening a saved result does not.
