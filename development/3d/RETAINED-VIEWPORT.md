# Retained GPU construction geometry

The main Studio construction view now uses `GpuWorldViewport3`. Immutable world triangles and authored wire endpoints upload only when the captured geometry changes. The shader applies the camera transform/projection; triangle clipping uses the rasterizer, while wire endpoints are explicitly near/far clipped before perspective division and expanded into portable screen-width quads. Orbit writes an 80-byte uniform instead of transforming, clipping and repacking every vertex on the CPU.

Positions are normalized around a captured local center before f32 upload. Camera data uses the same local scale. Invalid normalized camera ranges fail explicitly. Depth bias on the surface pipeline preserves coplanar construction edges; it affects this raster preview only. Final geometric visibility, generated hatch, paper strokes and exported plans remain unchanged. The host shares the existing worker-owned GPU device, validates shader/pipeline creation, and recreates the viewport with a replacement device. Explicit disposal releases its vertex, wire, uniform and depth resources.

The benchmark retains the old CPU-projected viewport as a reference. Four real-GPU fixtures compare surface interiors and wire neighborhoods for orthographic/perspective projection, near/far crossings, a 1e9 coordinate translation and 1e-9 geometry scale. All pass: three or four surface pixels differ out of roughly 45k interior pixels, below the stated raster tolerance, and all reference wire pixels have a matching wire within one pixel. These pixel checks validate construction rendering only; they are never a final-vector oracle.

On the source server, the 20k-triangle/20,200-wire worker test improves from roughly 6.7 FPS to 40–42 FPS including camera update, raster submission, bitmap creation and GPU queue completion. Across 13 frames there is exactly one geometry upload (1,204,800 bytes) plus 1,040 uniform bytes. Resident viewport buffers total 1,204,880 bytes; with the shared interval buffers the peak is 9,593,488 bytes, plus the 3,763,200-byte depth texture. Main-thread presentation is excluded from this worker measurement.

A separate main-Studio Playwright test generates the same large grid, opens its construction view, continuously moves the pointer for 120 animation frames, and counts actual bitmap presentations. It observes 118 presented frames over 3,957 ms (29.8 FPS), with zero render requests and unchanged plan identity. This is approximately the 30 FPS pilot target, not the worker's higher frame rate. It includes the UI/worker round trip and presentation cadence. Source small-scene Studio orbit, picking and byte-identical SVG export checks also pass.

Reproduce the direct workload with `tools/benchmark-three.mjs`; reproduce actual Studio presentation with `tools/benchmark-studio.mjs`. Both use Playwright and the NVIDIA adapter. The larger vector-classification benchmarks remain CPU-refinement/transfer bound; this change accelerates construction orbit, not final visibility. Camera commitment, independent reference fixtures, GPU timestamp instrumentation and broader M5 hardening remain unfinished.

Full isolated-image `pnpm check` passes: Rust 10.6s, TS 21.3s, library types 5.3s, Studio types 4.9s, live docs 12.9s, ink 15.1s, build 35.9s and smoke 2.2s. Existing drawing ink is unchanged; WASM remains `615f9d1b7a63396d451fd33aac18b559`. Source benchmark and UI timing reports are retained separately from served-bundle results.

Served-bundle checks confirm 24.4 ms warm worker frames (41.0 FPS), versus 148.8 ms for the reference renderer. The actual Studio presents 118 frames over 3775.4 ms (31.3 FPS) during continuous dragging, with unchanged plan identity and no sketch render requests. All four projection/clipping fixtures and all six CPU/GPU interval benchmarks pass. Original production container identities and start times remain unchanged.

The deployed bundle also passes all eight live examples, main Studio face picking, unchanged SVG after orbit, and the real-store save/reopen test with changed library responses and preview camera. Evidence is in playwright-retained/report.json, construction.json, construction.png and persistence.json. The benchmark-retained directory contains the large worker/UI reports and actual Studio screenshot.
