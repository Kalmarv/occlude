# Retained paper composition and camera commitment

`commitCamera3(previousRun, scene, camera, { compute3?, signal? })` creates a new execution from retained composition. It does not call the procedural sketch function or consume its RNG. The changed scene shares captured world geometry and receives a new explicit camera/classification; unrelated scenes reuse their immutable classification. The original execution remains exportable. The new execution carries resolved paper/pen configuration, plan options, draw request and modeling provenance.

Deferred `lineArt3` nodes retain their drawing instructions automatically. `drawing3(scene, (view, t) => tree)` retains custom feature selection and stroke styling. Its narrow `t.strokes3` interpreter resolves against the current execution's paper frame; the callback receives the actual new classified snapshot. Modeling/random draws happen outside that pure callback. Ordinary labels, masks, clipping, groups and modifier stacks remain in composition order. Captured 2D values retain physical-length prototypes and own their data; pure functions remain functions rather than being serialized.

Eager toolkit `t.strokes3` output remains fixed projected data. Attempting to commit another camera for its originating scene fails explicitly instead of silently rebinding stroke edits. Use the retained callback when interpretation should follow the camera. This API does not claim automatic replay of arbitrary imperative edits or mutable callback closures.
