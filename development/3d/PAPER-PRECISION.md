# Runtime paper precision budget

The GPU scene classifier now derives its source-parameter refinement tolerance from the physical camera frame. The execution supplies `min(0.005 mm, minimum resolved pen width / 20)`. Taking every resolved pen is conservative and supports later interpretations of the same cached classification; selection predicates need not execute twice to discover participating pens. Pen definitions are captured per execution. Camera commitment recomputes the bound for the changed frame.

Half of this budget is allocated to interval reconstruction; half is reserved for f64 projection arithmetic. The current input geometry is explicitly polygonal/straight-segment geometry, so there is no smooth-surface tessellation approximation to allocate. This is a tested working budget, not a numerical guarantee across arbitrary floating-point inputs. The allocation does not establish a formal bound on projection rounding or repair unrepresentable source details. Existing planner input snapping occurs afterward and remains separate. `crates/occlude-core/src/snap.rs` rounds each input coordinate to a 0.005 mm grid: the geometric grid displacement is at most 0.0025 mm per axis, or approximately 0.003535534 mm in 2D, aside from floating-point rounding. Intersection results are not snapped. This separate downstream displacement can exceed the deliberately microscopic nib budget; the new budget controls the additional 3D interval error, not that established 2D grid.

For an orthographic segment the projected speed is `paperHeight / span * hypot(dx, dy)`. For perspective, write endpoint depths as `d0,d1 > 0`. The maximum speed is the projected endpoint distance times `max(d0,d1)/min(d0,d1)`: the rational projection derivative peaks at the closer endpoint. The maximum across all clipped features bounds every streamed candidate pair, including off-page overscan. The tolerance is capped at the previous `1e-5`, so ordinary scenes cannot become coarser. Overflow tightens the bound to the smallest positive f64 value; WGSL receives zero and uncertain cuts take the CPU refinement path. Statistics expose both `paperToleranceMm` and `parameterTolerance`.

## Evidence

`three-paper-budget.test.ts` checks sampled displacement bounds for all 36 analytical fixtures, invalid/subnormal budgets, narrowest resolved pen propagation across executions, shared classifications, and camera commitment. The hardware precision worker adds four explicit negative controls: orthographic/perspective projection on a 10,000,000 mm frame with a 0.3 mm nib, and a 100 mm frame with a deliberately microscopic 0.000001 mm nib. These are stress cases, not practical paper/pen recommendations.

The unchanged low-level GPU classifier with the old fixed tolerance produces 0.2980232238769531 mm error on the huge frame and 0.0000029802322387695312 mm on the thin-nib case. Both exceed their respective budgets (0.005 mm and 0.00000005 mm). The new scene-level tolerance triggers one CPU refinement per case and matches the analytical endpoints exactly on the measured hardware. All 36 existing precision cases still pass.
